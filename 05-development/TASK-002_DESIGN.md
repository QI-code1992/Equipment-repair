# TASK-002 认证、权限、审计与设备基础设计

## 1. 输入与范围

- 输入基线：`42098613ffa20faed3bb0dcb842a0121722565bd`（`codex/stage-05-integration`）。
- 需求：FR-001、FR-010、FR-011、NFR-001、NFR-009；AC-001—008、AC-038、AC-039。
- 本任务交付平台账号、角色与菜单/操作权限、会话、审计、幂等键、组织树及设备主数据。
- 不交付 Agent 编排、知识检索、维修闭环，且不建立工厂或设备行级授权关系。

## 2. 方案与边界

采用 PostgreSQL、SQLAlchemy 与 Alembic 的单一持久化模型。认证使用服务端保存的会话记录：登录后向客户端返回随机 Bearer 会话令牌；数据库只保存令牌摘要和过期时间，认证依赖从 Bearer 令牌恢复当前用户。该方案不要求新增认证中间件框架，且可撤销会话。

角色通过关联表拥有权限；权限以 `resource:action` 字符串表达，例如 `equipment:read`、`equipment:write`。路由以明确的权限依赖保护，认证只判断账号、角色、菜单/操作权限，不按组织、工厂或设备过滤数据。

所有受保护的写请求要求 `Idempotency-Key`。同一用户、方法、路径和键在首次成功执行后复用已保存的响应；键被同一用户用于不同请求目标时明确拒绝。审计事件记录操作者、操作、资源、结果及安全净化后的元数据；不得写入密码、会话令牌、Cookie、密钥、原始思维链或敏感附件正文。

## 3. 数据与 API 设计

首个 Alembic revision 创建以下模型及约束：

- `User`：唯一用户名、密码摘要、启用状态、创建/更新时间。
- `Role`、`Permission` 与关联表：角色—权限多对多；权限唯一键为 `resource:action`。
- `Session`：令牌摘要唯一、用户外键、过期时间、撤销时间。
- `Organization`：可空父节点外键形成树。
- `Equipment`：唯一 `code`、组织外键、启用状态。
- `AuditEvent`：操作者、操作、资源类型/标识、结果、净化元数据与时间。
- `IdempotencyKey`：用户、HTTP 方法、路径、键、响应状态和响应体；组合唯一。

最小 API 集为登录、登出、当前用户读取、角色/权限查询、组织与设备的受保护读取/写入。受保护写操作响应含 `audit_event_id`。设备的启用状态在 TASK-002 保存；存在待处理或维修中故障时的停用保护，待 TASK-003 创建真实故障与维修事实后再实现和验证，TASK-002 不虚构维修表或状态。

## 4. 失败处理与安全规则

- 缺失、失效或撤销会话返回未认证错误；认证成功但缺少操作权限返回禁止错误。
- 重复设备编码由数据库唯一约束和 API 校验共同拒绝。
- 活跃故障设备的停用保护不在 TASK-002 实现；TASK-003 以真实故障与维修事实完成该业务校验及失败测试。
- 审计净化在写入前执行，测试以密码和会话令牌证明其不落库。
- 迁移升级和降级均作为 TASK-002 验证内容；不执行生产数据删除。
