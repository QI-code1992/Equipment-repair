# TASK-010 正式前端与批准流程集成设计

## 目标与边界

在 TASK-006-FE 已合入的 TypeScript 正式前端中，以已合并的业务与 Agent API 替换工作台、故障上报和维修执行页面壳。实现真实流式对话、引用显示、故障诊断的采纳/直接开始边界、结束维修时的 AI 摘要显隐，以及加载、空、错误、权限与不可用降级状态。

本任务不复制或运行 `03-ui-prototype/`，不修改已完成的智能配置页，不修改后端、公开 API、数据库、部署配置或业务规则，不新增生产依赖。

## 方案比较

1. **一次性重建完整原型页面**：视觉还原快，但会复制 Stage 3 实现并混入静态演示状态，违反正式工程边界；不采用。
2. **增量页面集成（采用）**：保留应用壳、路由、`api.ts` 和智能配置页；为工作台、故障上报、维修执行各自添加最小页面组件与交互测试。页面只消费既有 API，以显式 UI 状态表达权限与降级；可逐页测试和回退。
3. **抽象通用 Agent 框架后接入页面**：复用潜力较高，但当前只有 TASK-010 的真实调用点，会引入无需求支撑的抽象层；不采用。

## 页面与组件边界

| 单元 | 职责 | 依赖 |
| --- | --- | --- |
| `api.ts` | 扩展已有浏览器请求边界，定义已合并 API 的最小请求/响应类型、幂等请求和 SSE 读取 | 浏览器 `fetch`、既有后端契约 |
| 工作台页 | 展示受权限保护的健康分/入口状态；没有数据或无权限时给出明确状态 | 健康分读取 API |
| 故障上报页 | 人工正式上报与 AI 故障上报确认提交；对提交错误、权限失败与 Agent 不可用保持人工路径 | 故障上报、AI 故障上报 API |
| 维修执行页 | 启动服务端诊断、展示约三秒的阶段加载和真实事件、折叠引用；只在 READY 时允许采纳；始终提供直接开始 | 故障诊断、开始维修、结束维修 API |
| 维修结果区 | 提交维修人员最终结果；仅 `ADOPTED` 工单在“备件更换说明”之后显示只读 AI 摘要 | 维修结束 API、诊断草稿返回值 |

组件保持页面内聚。只有当前已有第二调用点的 HTTP/SSE 请求代码留在 `api.ts`；不创建通用 Agent 框架或复制原型组件。

## 数据与交互流程

1. 页面以受控请求加载所需业务上下文。API 返回 `401/403` 时显示“无权限”，不以静态数据模拟成功；网络/服务错误显示可重试提示。
2. 故障上报同时提供人工字段提交和 AI 草稿确认提交。写请求带 `Idempotency-Key`；成功后显示后端返回的故障标识，不在客户端伪造记录。
3. 用户在维修执行页选择故障后，页面只向 `POST /api/agent/fault-diagnosis` 发送允许的启动参数。客户端不提交服务端拥有的会话、根因或方案。页面将服务端 `diagnosis_draft_id` 留作后续回答/证据和采纳引用。
4. 页面为 `OPEN_LOADING` 显示“理解故障—检索同类维修—检索知识库—形成首问”的约三秒阶段状态；随后读取服务端 SSE 真实 token、引用和状态事件。消息区独立滚动，输入区固定在对话面板底部。
5. 引用仅使用服务端返回的文档/片段标识和摘要；默认折叠，可展开。没有真实引用时不渲染伪引用。
6. 只有服务端状态为 `DIAGNOSIS_READY` 才显示“采纳 AI 建议并开始维修”。采纳使用 `ADOPTED + diagnosis_draft_id`；直接开始使用 `DIRECT` 且不携带草稿。`UNAVAILABLE`、超时、证据不足或权限失败均保留直接开始维修。
7. 结束维修始终由维修人员提交最终原因、方案和结果。只有采用诊断的工单在备件更换说明之后显示只读 AI 摘要；直接开始或无摘要时隐藏该区域。

## 错误、安全与降级

- 不向页面状态、日志、测试或 UI 输出原始思维链、凭据或附件正文。
- 客户端只显示后端允许公开的错误码/字段提示；不把受保护详情写入错误文案。
- 对同一写操作的重试使用同一调用期生成的幂等键；不同操作生成新键。
- SSE 断开、Agent 配置无效、RAGFlow/LLM 超时或诊断未就绪时，不生成根因、方案或引用；保留人工提交、直接开始和人工结束维修。

## 验证策略

先为下列外部行为写失败测试，再做最小实现：

- API 客户端：请求路径、幂等头、错误映射与 SSE 事件解析。
- 工作台/上报：加载、空、错误、权限拒绝和人工流程可用。
- 维修执行：三秒加载状态、真实流式消息、引用折叠、证据不足无采纳、READY 采纳、不可用直接开始。
- 结束维修：`ADOPTED` 摘要仅在备件更换说明之后展示，`DIRECT` 隐藏。
- 应用路由与静态原型隔离。

完成时运行 `npm --prefix codebase/frontend test`、`npm --prefix codebase/frontend run build`、全部 `06-testing/tests/*.test.js`、浏览器关键流检查和 `git diff --check`。Docker、真实 RAGFlow 与后端环境联调由具备环境的 DEV-001 复核并记录，不能由前端 mock 替代。
