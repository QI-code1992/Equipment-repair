## GitHub 工作机制

### 从基线创建工作区

```bash
git fetch --tags origin
git switch -c codex/frontend-test001-portal-pages-f61348d baseline/frontend-collaboration-f61348d
# 或：git switch -c codex/frontend-test002-shell-standalone-f61348d baseline/frontend-collaboration-f61348d
```

每人使用独立 Git worktree；不得共享未提交修改。

此前创建的 `codex/frontend-dev001-*` 与 `codex/frontend-dev002-*` 空分支已废止，不得开始开发；为保留审计痕迹不删除。

### 开发、提交与 Push

1. 只编辑自己拥有的文件。
2. 每完成一个可预览页面或交互单元，创建可恢复 Commit。
3. 提交前运行页面相关 Vitest、`npm run build`、`git diff --check`。
4. `git status` 若出现对方拥有的文件，立即停止并通知 TEST-002，不得覆盖、暂存或提交。
5. 仅 Push 自己的任务分支；禁止 Push 到 `main`、`codex/stage-05-integration`、基线标签、对方分支或集成分支。

### PR 与集成

- 每个任务只维护一个 Draft PR，目标为 `codex/frontend-ui-integration-f61348d`。
- TEST-001 审核 TEST-002；TEST-002 审核 TEST-001；HEAD 改变后必须重新审核。
- 审核通过不等于可以自行合并。TEST-002 负责集成；若 TEST-002 是 PR 作者，由 TEST-001 执行获批的手动 Merge Commit。
- 只有已合并至集成分支、通过构建与健康检查、并经项目负责人确认的精确 Commit 才可部署 ECS。任务分支、Draft PR 和本地未提交代码不得部署。

## 冲突、差异与每日交接

- 原型与需求、API 或现有行为冲突：停止受影响页面，登记 `workflow/CHANGE_REQUESTS.md`；不得自行新增或删除功能。
- 两个任务都需要改 `App.tsx`、`styles.css`、`api.ts`、路由、权限或部署文件：暂停，由 TEST-002 创建明确的集成任务后再改。
- 每日交接必须写明：任务/分支/精确 HEAD、完成页面、进行中页面、修改文件、测试结果、未验证项、需要对方处理的共享样式事项、是否可请求审核。
