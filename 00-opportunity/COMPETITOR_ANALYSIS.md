# Competitor and Substitute Analysis（Candidate）

状态：**Candidate / Awaiting user confirmation**。本文件是机会阶段假设，不构成竞品结论或 Stage 0 批准。

## 已知替代与假设比较

| 方案 | 已知能力/优点 | 可能缺口（需验证） | 本项目假设差异 |
|---|---|---|---|
| 电话、群聊、Excel/纸单 | 无需部署，人员熟悉 | 状态、SLA、附件和审计分散；难形成可计算历史 | 统一故障—维修闭环和审计 |
| 通用工单/ITSM | 工单、权限、报表通常成熟 | 未知其对装载机字段、健康评分和设备授权的适配 | 设备领域规则与统一健康分服务 |
| 工程机械厂商售后平台 | 可能接近设备与服务网络 | 多品牌/跨组织数据可见性、知识引用和定制能力未知 | 受控多设备运维与可引用 AI |
| 独立知识库/通用聊天机器人 | 检索或问答上手快 | 不应写业务事实，数值准确性和权限边界需额外建设 | RAGFlow/LangGraph 仅作受控检索、路由和总结 |

## 证据边界

以上仅依据 workspace 中的产品与技术文档推导；没有外部市场访谈、竞品试用、价格/合同、客户名单、市场份额或胜负案例。因此：竞品名称、市场规模、可替代性强弱、客户愿意支付的溢价均为**未知市场证据**，不得当作已验证结论。

## 需要的竞争验证

- 访谈至少 3 类角色（维修、设备管理、采购/负责人），记录现有工具、切换阻力和预算。
- 对 2–3 个通用工单/厂商系统做同一故障闭环脚本演示，比较字段、权限、SLA、审计和 API 能力。
- 用真实样本测量人工基线，再与平台 MVP 的完成时长、错误率和引用可追溯性比较。
