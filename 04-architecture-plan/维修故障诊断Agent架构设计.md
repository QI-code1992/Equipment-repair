# 维修故障诊断 Agent 架构设计

- 阶段：Stage 4 — Architecture and Development Plan
- 状态：已确认设计，待实施计划审批
- 关联需求：`01-requirements/PRD.md` 第 12 节、`01-requirements/SPEC.md` 第 12 节、CR-024
- 上游基线：`baseline/stage-01-requirements-v1.1`、`baseline/stage-02-interaction-v1.0`、`baseline/stage-03-ui-v1.0`

## 1. 目标与边界

为使用平台账号、经公网访问的外部维修人员提供接单前故障诊断。系统应在用户设备/工厂授权范围内查询本地结构化历史维修记录、检索本地 RAGFlow 知识库，并经受控网关调用外部 LLM API 生成流式追问、根因分析、检查清单和维修建议。

RAGFlow 仅负责知识库文档检索和引用；同类设备历史维修记录必须从本地结构化数据库查询。业务事实、权限判断、采纳结果和维修最终字段只能由业务 API 写入。

## 2. 部署与信任边界

```text
公网维修人员浏览器
  -> HTTPS/WAF/API 网关
  -> 业务 API（认证、授权、审计、写入）
     -> 本地结构化数据库（历史维修记录）
     -> 内网 Agent 编排服务
        -> 本地 RAGFlow（知识库检索）
        -> LLM 网关 -> 外部 LLM API
```

- 公网仅开放前端与业务 API 的 HTTPS 入口。
- 数据库、RAGFlow、Redis、对象存储和 Agent 编排服务只位于内网。
- 平台账号认证后的每个工单、设备、工厂、附件、历史案例和引用都必须重新执行服务端授权。
- 外部 LLM API 只能经 LLM 网关调用，不允许浏览器或 RAGFlow 直连。

## 3. 诊断数据流

1. 用户打开故障单或开始维修，业务 API 校验设备、工厂和工单权限并创建受控诊断会话。
2. 故障单创建后，预诊断任务异步读取工单上下文、查询授权范围内的结构化历史维修案例、检索本地 RAGFlow 知识库，并保存可复用草稿；删除故障单时同步清理草稿。
3. 开始维修时优先读取草稿，前端保持约三秒的“历史案例检索—知识库检索—模型分析”可感知加载；未命中或过期时重新生成。
4. Agent 编排服务汇总已授权的案例、知识库引用和对话上下文，经字段白名单与脱敏后调用外部 LLM API，并将 SSE 事件转发给前端。
5. 证据不足时 Agent 继续追问；报警码选择“有”后必须提供具体报码或明确未读取。证据充分后才产生可采纳诊断。
6. 采纳时业务 API 写入可编辑预填字段与只读对话摘要；直接开始维修不保存 AI 临时诊断。结束维修以维修人员最终提交字段为准。

## 4. 服务职责

| 组件 | 职责 |
|---|---|
| 业务 API | 平台账号认证、设备/工厂/工单授权、业务写入、附件访问控制、审计 |
| 历史维修查询服务 | 在本地结构化库按设备型号、系统、故障特征查询案例，并强制授权过滤 |
| RAGFlow 适配器 | 本地知识库检索、文档状态、分段引用与引用 ID 返回 |
| Agent 编排服务 | 诊断会话、工具调用、动态追问、证据阈值、流式事件与采纳判定 |
| LLM 网关 | 字段白名单、脱敏、API 凭证隔离、限流、超时、重试和调用审计 |
| 预诊断任务 | 创建/复用/删除预诊断草稿与结果版本控制 |
| 审计与摘要服务 | 记录授权决策、工具调用、采纳结果；生成已采纳工单的只读摘要 |

## 5. 安全与降级

- 外部 LLM 不接收账号凭证、内部地址、完整附件原件、未授权案例或未授权知识库文本。
- LLM 调用失败、超时或配置不完整时，返回明确的“AI 诊断暂不可用”，人工仍可直接开始维修。
- SSE 断线仅恢复已持久化事件；禁止伪造未完成模型内容。
- 历史案例和知识库引用均只显示给当前用户有权访问的范围。

## 6. 验证基线

- 权限隔离：跨设备、跨工厂、跨工单查询必须被拒绝且审计。
- 数据来源：历史案例来自结构化数据库；知识库引用来自本地 RAGFlow。
- LLM 网关：验证脱敏、超时、重试、限流和失败降级。
- Agent 会话：验证 SSE 流式、断线恢复、报警码必填、证据不足不采纳。
- 生命周期：验证预诊断创建、复用、过期重算和故障单删除清理。
- 数据边界：验证采纳后的预填与摘要，以及直接开始维修不保留 AI 临时数据。
