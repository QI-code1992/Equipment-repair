# 工作台原型融合设计

- 变更编号：CR-023
- 阶段：Stage 3 — UI 与高保真原型
- 状态：设计已获项目负责人批准；等待设计文档审阅确认
- 设计时间：2026-07-14
- 输入文件：`equipment-repair-prototype-workbench-filter-link-updated-2026-07-14.zip`
- 目标原型：`03-ui-prototype/prototype/`

## 目标

将输入压缩包中的工作台页面融合到现有原型，使工作台的页面结构、视觉表现和交互行为以输入版本为准；除工作台及其必要的隔离依赖外，现有原型页面与共享能力保持不变。

## 已批准方案

采用“页面级移植 + 依赖最小适配”。不整包覆盖输入压缩包的旧版原型，也不覆盖现有共享 `app.js`、`app.css` 或 `global-agent.js`。输入压缩包中的共享文件仅作为识别工作台依赖与行为的参考。

## 范围

### 纳入

- 替换 `03-ui-prototype/prototype/pages/workbench.html` 的工作台内容。
- 适配该页面专用的样式、数据、事件与可访问性属性；工作台专用逻辑必须局限于工作台页面，或使用具名且无副作用的隔离脚本。
- 保持以下输入版本交互一致：组织范围筛选、指标卡与故障待办标签联动、故障卡筛选与状态展示、设备详情跳转、健康风险统计、趋势时间范围与自定义日期展示、刷新反馈。
- 为融合后的工作台补充静态交互回归检查，并保留现有全局回归检查。

### 不纳入

- 不覆盖或回退其他页面、共享导航、全局 AI 助手、通知面板、登录与用户入口。
- 不将输入压缩包中的整套 `assets/app.js`、`assets/app.css`、历史 `data-import` 页面、旧服务脚本或旧测试目录直接复制到当前原型。
- 不改变已存在的页面路由和其他页面的视觉、交互或数据。

## 集成结构

1. 以输入包 `pages/workbench.html` 为工作台结构和交互的视觉来源。
2. 对现有共享资源存在依赖的部分，优先复用当前资源；仅当无法表达输入行为时，新增以 `workbench-` 命名的页面级样式或脚本。
3. 所有工作台链接继续使用当前原型的相对路径；故障卡“查看详情”使用 `equipment-detail.html?device=<id>`，不得新增其他页面入口。
4. 输入数据仅作为静态原型演示数据；不将其宣称为生产接口或真实运行数据。

## 验收标准

- 工作台在本地原型服务中可正常加载，无 JavaScript 语法错误。
- 组织范围选择会同步影响指标、待办、健康统计与趋势展示。
- 指标卡与待办标签可双向切换同一筛选状态；默认状态、空状态和高风险筛选可呈现。
- “查看详情”链接保留设备参数并跳转到现有设备详情页。
- 趋势范围可切换近 7 天、近 30 天和自定义日期；刷新操作提供输入版本对应的更新时间反馈。
- 现有所有原型静态检查继续通过；非工作台页面不发生内容变更。
- 完成后记录 `PCP-012`，写明 Commit SHA、验证命令、证据与恢复方式，并提交、推送至 GitHub。

## 风险与控制

- 风险：输入包是旧版完整原型，直接复制共享资源会回退现有全局能力。
  - 控制：只迁移工作台和必要的隔离依赖；对共享资源改动设置为零。
- 风险：工作台依赖共享健康分或全局组件时可能与现有版本不一致。
  - 控制：优先调用当前原型已提供的能力；新增检查覆盖关键筛选与跳转标识。
- 风险：工作台替换可能误改其他页面。
  - 控制：实施后核验 Git 变更范围仅限工作台、专用测试、Stage 3/工作流记录。

## GitHub 与恢复

- 设计、实现、测试证据和检查点均须提交并推送到 `origin`（`QI-code1992/Equipment-repair`）。
- 工作台稳定后，检查点以普通提交保护；未获 Stage 3 基线审批前不创建里程碑标签。
- 恢复采用 `git restore --source <checkpoint-sha> -- 03-ui-prototype/prototype/pages/workbench.html`，必要时同时恢复该检查点记录的专用测试或隔离资源。
