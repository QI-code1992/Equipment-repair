# 原型页面与 PRD / SPEC 一致性审计

- 审计日期：2026-08-07
- 原型基线：`03-ui-prototype/prototype/`，Stage 3 已批准基线
- 对照文档：`01-requirements/PRD.md`、`01-requirements/SPEC.md`
- 辅助对照：`02-product-interaction-design/PAGE_FUNCTION_MATRIX.md`、`03-ui-prototype/PROTOTYPE_BASELINE.md`
- 审计方式：逐页检查原型 HTML 的页面结构、模块、按钮、表单、状态和共享脚本，再对照 PRD/SPEC 的页面清单、功能要求、路由契约、权限和状态；未将生产代码实现当作需求证据。

## 一、审计结论

原型的 14 个正式页面与 PRD 的 14 页面清单总体一致，工厂建模、Agent 上报、智能配置、接单前诊断等此前遗漏或描述过粗的内容已经写入 PRD/SPEC。原型也明确包含共享的通知入口和悬浮 Global Agent。

但当前仍有以下边界没有在 PRD/SPEC 中完全收敛：

1. `/maintenance-records/:id` 被 SPEC 描述为独立详情页面，原型实际是维修记录页内的详情模态框。
2. `/workbench` 是 SPEC 候选路由，原型文件是 `workbench.html`，现有生产实现使用 `/`；路由真值未统一。
3. 登录页的“忘记密码”以及系统管理中的“修改密码”有原型交互，但 PRD/SPEC 没有完整定义。
4. BI 原型的摘要、趋势、效率、组织筛选、日/周/月切换、图表切换和历史对比，在 PRD/SPEC 中没有形成同等粒度的页面功能契约。
5. “智能审计”不是 Stage 3 独立原型页面；它来自后续 API-007/实现扩展，不能声称是原型一比一页面。
6. SPEC 的“所有角色均可使用 AI floating Agent”与 PRD FR-005、AC-003 的“必须具备悬浮 Agent 权限”冲突。
7. 原型脚本仍残留“数据导入”文案，但 PRD 明确将数据导入列为 Non-goal；不得据此恢复数据导入页面、菜单或 API。

在这些问题解决前，前端整改只能对有明确原型来源的页面做一比一还原；对智能审计、独立维修详情页和未定义的密码流程不得自行扩展范围。

## 三、PRD 对照结果

### 已对齐项

- PRD 6.0 已正确列出 14 个正式页面，且明确 Global Agent 是悬浮抽屉、工单嵌入业务流程而非独立页面。
- FR-001 至 FR-012 覆盖设备、知识、人工/AI 上报、Agent、问数、诊断、维修、健康分、系统管理、工厂建模和智能配置。
- PRD 第 12 节已覆盖原型中的接单前诊断候选增量：3 秒加载、动态问题、报警码、证据不足、采纳/直接开始和 AI 摘要。
- PRD FR-005 与原型一致：Global Agent 有三个独立 Tab，关闭不清除历史，正式提交回到 Agent 上报/故障上报边界。

### 不一致或不足

| ID | 严重度 | 对照点 | 原型事实 | PRD 当前表述 | 处理建议 |
|---|---|---|---|---|---|
| PRD-UI-001 | 高 | 登录 | 有“忘记密码”入口和提示/弹层 | 仅写登录、登出，未定义忘记密码流程 | 明确是仅提示入口还是正式找回密码流程；未确认前不得实现完整找回流程 |
| PRD-UI-002 | 中 | BI | 有管理摘要、趋势、效率、筛选、日/周/月、历史对比和关注 | P0 只列“驾驶舱 BI”，健康分章节有数据规则，但缺少页面交互契约 | 在 FR 中补充 BI 页面模块、筛选、图表切换、空/错态和历史对比 |
| PRD-UI-003 | 高 | 维修详情 | 详情为 `maintenance-records.html` 内模态框 | 页面清单只写维修记录，未明确详情形态 | 明确详情模态框；禁止把 `/maintenance-records/:id` 解释成新的独立视觉页面 |
| PRD-UI-004 | 中 | 系统管理密码 | 原型“我的账号”有修改密码 | FR-010 未定义密码修改字段、校验、会话失效和审计 | 补充正式密码修改契约；若仅保留占位提示，应在原型和 PRD 中一致标注 |
| PRD-UI-005 | 中 | 智能审计 | 原型没有独立智能审计页，调用记录在智能配置中 | PRD FR-010 有审计日志，FR-012 有调用记录，但没有 `/intelligence-audit` | 将智能审计独立路由标为非原型扩展；如需保留，新增变更请求并确认视觉范围 |
| PRD-UI-006 | 低 | 数据导入残留 | 原型脚本/示例仍出现导入文案，但无正式页面 | Non-goal 明确排除数据导入 | 清理残留文案或标注为历史快照，不恢复菜单/权限/API |

## 四、SPEC 对照结果

### 已对齐项

- SPEC 页面契约覆盖原型的主要 14 页及 Global Agent 抽屉。
- SPEC 的数据契约覆盖设备、故障、工单、健康分和知识文档字段，与原型表单和详情区域相符。
- SPEC 的 Agent 状态机、诊断状态机和异常规则已把原型中的收集、预览、人工确认、证据不足、降级和直接维修边界结构化。
- SPEC 的权限、审计和 Agent 线程边界与原型的权限提示和受控入口方向一致。

### 不一致或不足

| ID | 严重度 | 对照点 | 原型/PRD 基准 | SPEC 当前表述 | 处理建议 |
|---|---|---|---|---|---|
| SPEC-UI-001 | 高 | Global Agent 权限 | PRD FR-005、AC-003：无悬浮 Agent 权限不得显示/调用 | 角色矩阵将 AI floating Agent 对四类角色全部写为 `Use/manage` | 改为“具有对应菜单/操作权限才可使用”；系统管理员的 manage 与普通使用权限分开 |
| SPEC-UI-002 | 高 | 工作台路由 | 原型文件为 `workbench.html`；当前生产协作基线使用 `/` | SPEC 写 `/workbench`，页面矩阵未给候选路由 | 统一唯一正式路由；若保留 `/`，SPEC 应改为 `/`，并把 `/workbench` 标为别名或删除 |
| SPEC-UI-003 | 高 | 维修详情形态 | 原型是列表页内详情模态框 | 页面契约将 `detail` 写成 `/maintenance-records` 必要状态，但实现任务又出现 `/:id` | 明确详情为同页模态框；独立 `/:id` 只有在单独确认后才能保留 |
| SPEC-UI-004 | 中 | 登录忘记密码 | 原型有入口 | Login 契约只有登录四态 | 补充“忘记密码”是提示型入口还是正式流程；不要仅从原型按钮推导 API |
| SPEC-UI-005 | 中 | 系统管理密码 | 原型有“修改密码” | 系统管理契约只概括用户/角色/日志，没有密码修改契约 | 明确字段、错误、会话失效、审计和权限；与现有密码 API 及原型统一 |
| SPEC-UI-006 | 中 | BI 页面状态和交互 | 原型有筛选、日/周/月、查询/重置、摘要/趋势/效率/历史对比 | BI 必要状态仅 default/empty/error/filter | 增加 period 切换、查询/重置、图表/列表、历史对比和关注交互的契约与状态 |
| SPEC-UI-007 | 中 | 智能审计 | 原型无独立页，调用记录在智能配置 | SPEC 页面契约没有智能审计，但后续 API/生产实现出现 `/intelligence-audit` | 在 SPEC 中明确该路由不属于当前原型基线；需要时走变更请求，不得作为页面整改范围 |
| SPEC-UI-008 | 低 | 维修导出 | 原型有导出按钮但当前能力受数据源/权限约束 | SPEC 页面契约和 PRD P1 对导出说明不够具体 | 标注为 P1/禁用态，明确不计入当前 P0 一比一功能完成 |

## 五、当前可执行的页面基线

### 可直接按原型一比一整改

登录、工作台、BI、工厂建模、设备台账/新增/编辑/详情、故障上报、Agent 上报、维修记录（含详情模态框）、维修执行、系统管理、智能配置，以及应用壳、导航、通知、悬浮 Global Agent。

### 不得直接按现有实现扩展

- `/intelligence-audit`：无独立原型，先确认是否保留为独立页或并入智能配置。
- `/maintenance-records/:id`：原型依据是维修记录列表页内模态框，不得凭空增加独立页面布局。
- 忘记密码完整流程：原型只有入口和提示，是否需要真实找回能力必须确认。
- 任何新页面、新卡片、新指标、新菜单、数据导入入口或与原型不一致的权限入口。

## 六、建议的文档收敛顺序

1. 先确认 `PRD-UI-001`、`PRD-UI-004` 的密码流程范围。
2. 统一工作台正式路由（`/` 或 `/workbench`）。
3. 将维修详情明确为列表内模态框，并从页面任务中移除独立详情页表述。
4. 修正 SPEC 的 Global Agent 权限矩阵，使其与 PRD/AC-003 一致。
5. 决定智能审计是取消独立页、并入智能配置，还是提交新的产品变更请求。
6. 完成后再更新 PRD、SPEC、页面功能矩阵和前端协作任务书；在文档确认前不继续扩展智能审计或独立维修详情页。
