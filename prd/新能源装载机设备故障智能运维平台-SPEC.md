# 新能源装载机设备故障智能运维平台 SPEC

版本：v1.0  
日期：2026-06-24  
来源基线：`新能源装载机设备故障智能运维平台-PRD.md` v1.2  
状态：SPEC 初稿

## 一、文档说明

### 1.1 文档目的

本文档在 PRD 基础上细化产品规格，明确页面、功能、字段、状态、权限、Agent 行为、异常处理和验收口径，供原型设计、研发拆解、测试用例设计使用。

### 1.2 产品范围

本阶段建设新能源装载机设备故障智能运维平台，范围包括：

- 设备台账。
- 设备知识配置。
- RAGFlow 知识库集成。
- 人工表单故障上报。
- 全局运维Agent，包括 AI故障上报、智能问数、操作指引三个子 Tab。
- Agent 对话式故障上报，生成故障上报页的 AI待提交 单据。
- Agent 功能权限识别，包括 AI 悬浮框权限和故障上报功能权限。
- 基于 LangGraph 的 Agent 流程编排。
- 数据导入。
- Agent 智能诊断。
- 专家级维修建议。
- 草稿维修工单。
- 维修执行与记录沉淀。
- 设备健康评分。
- 简单驾驶舱 BI。
- 系统用户及权限管理。

### 1.3 架构边界

正式架构采用软件系统、LangGraph Agent、RAGFlow 三模块分工。

| 模块 | 规格边界 |
|---|---|
| 软件系统 | 管理业务数据、用户界面、权限、设备、工单、维修记录、健康评分、知识上传入口和结果展示 |
| LangGraph Agent | 编排意图识别、权限校验、缺失信息追问、RAGFlow 检索、业务数据查询、诊断生成、维修建议和草稿工单建议 |
| RAGFlow | 管理知识库、文档解析、切片、向量化、索引、检索、引用来源和文档处理状态 |

规则：

- Agent 必须使用 LangGraph 框架开发，并用 LangGraph 管理多节点状态流转。
- RAGFlow 不承担业务 Agent 流程编排。
- 软件系统不直接拼接 Prompt 进行诊断。
- RAGFlow 检索结果必须经 LangGraph Agent 结合业务上下文后输出。

## 二、角色与权限规格

### 2.1 角色定义

| 角色 | 可用端 | 说明 |
|---|---|---|
| 系统管理员 | Web | 管理用户、角色、权限、设备、知识配置和系统基础配置 |
| 设备管理员 | Web | 管理负责设备、审核诊断、确认工单、维护知识 |
| 维修人员 | Web | 接收工单、查看建议、执行维修、提交维修记录 |
| 司机/现场人员 | Web | 上报故障、查看本人提交事项进度 |
| 管理层/查看者 | Web | 查看驾驶舱、设备健康和故障处理概览 |

### 2.2 运维Agent权限规则

- 权限控制到 AI 悬浮框总入口，不控制到 AI故障上报、智能问数、操作指引三个 Tab。
- 用户具备 AI 悬浮框权限后，可进入三个 Tab。
- AI 悬浮框权限和故障上报功能权限来自系统管理中的用户管理和角色管理。
- AI故障上报创建 AI待提交 单据时，必须校验故障上报功能权限。
- 智能问数不做数据权限校验，不按设备负责人、部门或设备范围过滤结果。
- 操作指引不做 Tab 级权限限制。

## 四、功能规格

### 4.1 设备台账

#### 4.1.1 列表能力

- 支持按设备编号、设备名称、设备型号搜索。
- 支持按设备状态、设备负责人筛选。
- 支持分页、排序。
- 支持查看设备健康评分和当前工单状态摘要。

#### 4.1.2 设备字段

| 字段 | 必填 | 规则 |
|---|---|---|
| 设备编号 | 是 | 全局唯一 |
| 设备名称 | 是 | 不超过系统限制长度 |
| 设备型号 | 是 | 用于关联 BOM、参数和知识配置 |
| 设备类型 | 是 | 默认新能源装载机，可扩展 |
| 生产厂家 | 否 | 文本 |
| 出厂日期 | 否 | 日期 |
| 投入使用日期 | 否 | 日期 |
| 运行小时 | 否 | 非负数 |
| 设备状态 | 是 | 正常、故障、维修中、停用 |
| 设备负责人 | 否 | 用户，用于设备台账管理和责任展示 |
| 设备图片 | 否 | 图片 |

#### 4.1.3 异常规则

- 设备编号重复时禁止保存。
- 设备存在未关闭故障单或工单时禁止删除。
- 设备负责人为空时，设备管理员无法通过 Agent 操作该设备。

### 4.2 设备知识与自动知识图谱

#### 4.2.1 页面结构

设备知识能力合并到设备台账中，不再作为独立侧边导航。新增/编辑设备沿用现有原型内容，并新增“自动生成知识图谱”区域。

新增/编辑设备页面包含：

- 基础信息。
- 设备负责人。
- 额定参数。
- BOM 组成。
- 知识文档。
- 故障知识。
- 历史案例。
- 自动生成知识图谱。

设备详情页面采用 Tab 结构：

- 概览。
- BOM 组成。
- 额定参数。
- 知识文档。
- 故障知识。
- 历史案例。
- 知识图谱。

知识图谱由系统根据上传文件自动生成。人工只负责上传资料、查看解析状态、审核异常结果，不要求人工手动拖拽构建图谱。

#### 4.2.2 BOM 组成 Tab

能力：

- 支持上传 BOM 清单并自动解析生成 BOM 节点。
- 支持管理员审核、修正、停用 BOM 节点。
- 支持最多五级：整机、系统、总成/模块、部件、零件。
- 支持按设备型号复用。
- 节点可关联参数、文档、故障知识和历史案例。

异常：

- 父节点不存在时不允许保存子节点。
- 已关联故障知识、参数或历史案例的节点删除前需提示影响。

#### 4.2.3 额定参数 Tab

能力：

- 支持上传额定参数表并自动解析参数项。
- 支持自定义新增参数。
- 支持参数编码、单位、标准值、上下限、告警等级。
- 支持关联 BOM 节点。
- 支持停用参数。

规则：

- 同一设备型号下参数编码不可重复。
- 参数编码用于匹配导入运行数据字段。
- 上限、下限可以只填一个，也可以都不填。
- 未配置上下限的参数不参与阈值异常判断。

#### 4.2.4 知识文档 Tab

能力：

- 上传知识文档。
- 选择文档类型。
- 关联设备型号、系统或 BOM 节点。
- 查看解析状态。
- 查看切片状态。
- 查看索引状态。
- 停用文档。
- 文档上传后，软件系统将文档和 metadata 传输至 RAGFlow。
- RAGFlow 完成解析、切片、向量化和索引后，软件系统展示处理结果。
- 文档解析成功后，系统可基于 RAGFlow 返回的结果和业务 metadata 展示实体、故障现象、部件关系、维修建议和依据来源，用于生成知识图谱。

文档类型：

- 设备说明书。
- 维修手册。
- 故障码手册。
- 电气原理图。
- 液压原理图。
- 保养手册。
- 安全操作规范。
- 培训资料。
- 历史故障案例集。
- 厂家服务通告。

状态：

- 待上传。
- 上传中。
- 待解析。
- 解析中。
- 切片中。
- 索引中。
- 已就绪。
- 解析失败。
- 索引失败。
- 已停用。

规则：

- 解析失败或已停用文档不得被 Agent 引用。
- Agent 引用文档时应展示来源名称和文档类型。
- 软件系统需保存本地文档 ID 与 RAGFlow 文档 ID、数据集 ID 的映射。
- 文档 metadata 至少应支持设备型号、文档类型、BOM 节点、上传人、版本号和生效状态。
- RAGFlow 检索返回的片段不得绕过 LangGraph Agent 直接展示为最终诊断结论。

#### 4.2.5 故障知识 Tab

字段：

- 故障码。
- 故障名称。
- 适用设备型号。
- 关联 BOM 节点。
- 故障现象。
- 可能原因。
- 排查方法。
- 处理建议。
- 安全注意事项。

规则：

- 故障知识可由上传的故障知识库、维修手册、故障码手册和历史案例自动抽取生成。
- 自动抽取结果进入待审核状态，审核后才能作为正式故障知识参与 Agent 诊断。

#### 4.2.6 历史案例 Tab

来源：

- 维修工单关闭后自动沉淀。
- 历史案例文件批量上传导入。
- 管理员手动补充。

状态：

- 待审核。
- 已入库。
- 已驳回。

规则：

- 历史案例应关联设备、BOM 节点、故障知识、维修方案、工时成本和依据来源。

#### 4.2.7 知识图谱 Tab

能力：

- 自动展示设备为中心的知识图谱。
- 图谱节点包括设备、BOM 节点、额定参数、知识文档、故障知识和历史案例。
- 图谱关系包括“属于”“影响”“引用”“相似案例”“参数约束”“处理建议来源”。
- 支持点击节点查看详情和来源文件。
- 支持展示解析状态：待解析、解析中、已生成、生成失败、待审核。

规则：

- 知识图谱生成依赖上传文件和系统解析结果，不要求人工手动构建。
- 文件解析失败时，图谱应标记缺失来源，不得把失败内容纳入 Agent 可用知识。
- 图谱关系被管理员驳回后，不参与 Agent 诊断和维修建议。

- 待审核案例可供人工查看，但默认不作为 Agent 正式知识来源。
- 已入库案例可用于诊断相似案例推荐。

### 4.3 故障上报

#### 4.3.1 双入口

- 人工表单上报：用户在故障上报页面直接填写并提交。
- 运维Agent辅助上报：用户在全局右下角运维Agent的 AI故障上报 Tab 中通过对话生成故障上报页面的 AI待提交 单据。

AI待提交单据不是正式提交。用户必须在故障上报页面对该单据执行编辑、提交或删除。提交后状态变为待接单。

#### 4.3.2 字段规格

字段与故障上报新增页保持一致。

| 字段 | 必填 | 规则 |
|---|---|---|
| 选择设备 | 是 | 每次只能选择一台设备 |
| 所属车间 | 否 | 选择设备后自动带出 |
| 所属产线 | 否 | 选择设备后自动带出 |
| 紧急程度 | 是 | 非常紧急、紧急、一般；Agent 场景未选择时默认紧急 |
| 故障现象 | 是 | 用户描述设备异常表现 |
| 发生时间 | 否 | 不得晚于当前时间 |
| 可能故障位置 | 否 | 文本输入 |
| 故障说明 | 否 | 建议按“现象 + 条件 + 影响 + 已做的临时处置”组织 |
| 现场图片 | 否 | 图片附件 |
| 日志或视频附件 | 否 | 日志、视频或其他文件 |

#### 4.3.3 人工表单上报规则

- 提交前校验必填字段。
- 发生时间晚于当前时间时禁止提交。
- 提交成功后进入待接单状态。

#### 4.3.4 AI故障上报规则

- 进入 AI故障上报 Tab 后，具备故障上报功能权限的用户收到首句：`我可以帮你通过对话生成待提交故障单。请先选择设备。`
- 如果用户有 AI 悬浮框权限但没有故障上报功能权限，Agent 应在进入 Tab 时用对话提示：可咨询和整理信息，但无法创建 AI待提交 单据。
- 设备必须通过设备选择器选择，选择器字段为设备编号、设备名称、所属车间、所属产线。
- 设备选择器只允许选择一台设备。
- Agent 必须围绕选择设备、故障现象、紧急程度、发生时间、可能故障位置、现场图片、日志或视频附件进行追问。
- 额外辅助追问不超过 5 轮，结果归纳到故障说明。
- 统一附件入口支持图片、日志、视频等文件；预览时自动分组为现场图片、日志或视频附件。
- 当前版本不识别图片内容，不根据图片自动补充故障说明。
- 满足生成预览条件后，Agent 主动询问是否生成结构化预览，并提示非必填缺失项。
- 结构化预览只读，不允许在预览区直接编辑；用户需通过继续对话修改字段或补充信息。
- 预览底部操作为生成待提交单、继续对话、取消。
- 生成待提交单后，系统生成正式故障编号，状态为 AI待提交。
- 生成成功后不自动跳转，仅提供前往故障上报页查看的入口。

#### 4.3.5 AI待提交列表操作

AI待提交单据在故障上报页面列表中展示为状态 AI待提交，操作包括：

- 详情：查看当前结构化字段、故障说明和附件。
- 编辑：进入故障上报编辑表单。
- 提交：正式提交后状态变为待接单，故障编号保持不变。
- 删除：删除前二次确认。

AI待提交单据不设置有效期，不自动过期或删除；正式提交后按普通故障上报单处理，不展示运维Agent来源标识。

### 4.4 全局运维Agent

#### 4.4.1 面板结构

- 全局右下角悬浮入口名称为运维Agent，可简短显示 Agent。
- 点击后打开右侧抽屉，抽屉宽度约 560-640px。
- 抽屉包含三个子 Tab：AI故障上报、智能问数、操作指引。
- 首次打开默认 AI故障上报；关闭后再次打开回到上次所在 Tab。
- 三个 Tab 对话历史独立保存，页面跳转后不清除。
- 顶部控制仅包含清除当前 Tab 对话、关闭。
- 清除对话只清除当前 Tab 历史；关闭不清除历史。

#### 4.4.2 悬浮入口交互

- 悬浮入口可拖拽，拖拽后自动吸附右侧。
- 3 秒未点击、未悬停、未拖拽时半透明。
- 抽屉打开后悬浮入口隐藏。
- 抽屉不加全屏遮罩，允许操作底层页面。
- 正常不显示在线状态；仅异常时提示服务、API、附件上传等错误。
- 本阶段仅支持桌面 Web，不要求移动端适配。

#### 4.4.3 权限规则

- 权限控制到 AI 悬浮框总入口，不控制到三个 Tab。
- 用户有 AI 悬浮框权限后，可进入全部三个 Tab。
- AI 悬浮框权限和故障上报功能权限来自系统管理的用户管理和角色管理。
- 智能问数不做数据权限校验。
- AI故障上报创建 AI待提交 单据时校验故障上报功能权限。

#### 4.4.4 智能问数规格

- 支持查询全局业务数据，包括设备、故障、维修记录、工单进度、健康评分、驾驶舱 BI、数据导入结果。
- 正式系统必须调用后台 API 获取问数结果。
- 默认时间范围为近30天，用户可通过对话修改。
- 信息不足时，Agent 可主动追问时间范围、设备范围、指标口径、排序方式等关键条件。
- 支持多轮继承查询条件并重算结果。
- 回答可包含文字结论、指标卡片、图表、表格、Top排行、分布图。
- 支持复制结果、导出 Excel、生成可复制或下载的文本报告摘要。
- 支持带筛选条件跳转到相关业务页面。
- API 查询失败或超时时，保留上一轮成功结果，提示本次条件未更新，并提供重试。

#### 4.4.5 操作指引规格

- 支持当前页面帮助、跨页面流程指引、报错原因解释、权限或限制说明。
- 仅操作指引 Tab 显示当前页面上下文。
- 未理解用户需求前，不直接要求用户跳转。
- 默认给简短回答，支持展开详细步骤。
- 包含步骤时支持复制步骤。
- 可提供跳转入口，但不自动跳转，不做页面元素高亮。

#### 4.4.6 输入、附件与快捷问题

- 三个 Tab 使用统一输入栏：附件按钮、文本输入框、发送按钮。
- 当前 Tab 决定 placeholder 和附件用途。
- 每个 Tab 空历史时显示固定快捷问题；有历史后隐藏或弱化。
- 清除当前 Tab 历史后，该 Tab 快捷问题重新出现。

### 4.5 数据导入

#### 4.5.1 导入入口

- 故障码数据导入。
- 报警记录导入。
- 运行数据导入。

#### 4.5.2 导入校验

- 文件格式校验。
- 设备编号存在性校验。
- 时间格式校验。
- 必填字段校验。
- 参数编码匹配校验。
- 数值范围格式校验。

#### 4.5.3 导入结果

- 总行数。
- 成功行数。
- 失败行数。
- 失败原因。
- 导入人。
- 导入时间。

### 4.6 Agent 智能诊断

实现约束：

- Agent 必须由 LangGraph 框架承载。
- Agent 诊断流程至少应包含权限校验、上下文读取、RAGFlow 检索、业务数据查询、诊断生成和结构化输出。
- Agent 调用 RAGFlow 检索知识，不自行切片、向量化或维护向量索引。

#### 4.6.1 诊断输入

- 故障上报单。
- 故障码。
- 报警记录。
- 运行数据。
- 设备台账。
- BOM 节点。
- 额定参数。
- 知识文档。
- 故障知识。
- 历史案例。
- RAGFlow 检索片段和引用来源。

#### 4.6.2 诊断输出

- 故障类型。
- 风险等级。
- 是否建议停机。
- 可能原因排序。
- 置信度。
- 关联 BOM 节点。
- 异常参数。
- 关联故障码。
- 诊断依据来源。
- 需人工复核提示。

#### 4.6.3 降级规则

- 缺少 BOM 时，提示部件定位可信度降低。
- 缺少知识文档时，提示知识来源不足。
- 缺少历史案例时，提示暂无相似历史案例。
- 低置信度时必须标记需人工复核。
- RAGFlow 不可用或检索失败时，Agent 应提示知识检索暂不可用，并仅基于已授权业务数据输出低置信度建议或要求人工处理。

#### 4.6.4 推荐 LangGraph 节点

| 节点 | 作用 |
|---|---|
| `load_context` | 读取用户、角色、设备、当前会话上下文 |
| `detect_intent` | 判断上报、查询、诊断解释、维修建议、工单生成等意图 |
| `check_permission` | 校验 AI 悬浮框权限、故障上报功能权限和必要业务权限 |
| `collect_missing_info` | 追问缺失字段 |
| `normalize_fault_report` | 生成结构化故障摘要 |
| `retrieve_knowledge` | 调用 RAGFlow 检索知识 |
| `load_business_data` | 查询设备、工单、健康评分、维修历史 |
| `generate_diagnosis` | 生成诊断结果 |
| `generate_repair_advice` | 生成维修建议 |
| `draft_work_order` | 生成草稿工单建议 |
| `human_confirm` | 等待人工确认 |
| `final_response` | 输出前端可展示的结构化结果 |

### 4.8 草稿维修工单

#### 4.8.1 生成规则

- Agent 诊断完成后可生成草稿工单。
- 草稿工单包含故障摘要、风险等级、建议处理方案、建议备件、建议工时。
- 草稿工单必须由设备管理员确认后派发。

#### 4.8.2 状态

- 待接单。
- 维修中。
- 待验收。
- 已完成。
- 已撤回。
- 已驳回。
- 返修中。

#### 4.8.3 操作权限

- 设备管理员可确认、修改、派发、撤回草稿。
- 维修人员可接单、开始维修、提交维修结果。
- 系统管理员可查看和管理全部工单。

### 4.9 维修执行与知识沉淀

#### 4.9.1 维修执行字段

- 实际成本。
- 维修照片。
- 维修结果。
- 是否复检。

#### 4.9.2 关闭规则

- 实际故障原因必填。
- 实际处理方案必填。
- 维修结果必填。
- 关键字段缺失时不允许关闭工单。

#### 4.9.3 知识沉淀规则

- 工单关闭后生成历史案例。
- 能匹配已有故障知识时，追加为案例。
- 不能匹配时，生成待审核新故障模式。

### 4.10 设备健康评分

#### 4.10.1 展示位置

- 设备列表。
- 设备详情。
- 驾驶舱 BI。

#### 4.10.2 等级

| 分数 | 等级 | 说明 |
|---|---|---|
| 85-100 | 健康 | 当前风险较低 |
| 70-84 | 关注 | 存在轻微异常或维护风险 |
| 50-69 | 风险 | 存在明显故障或重复异常 |
| 0-49 | 高风险 | 建议优先停机检查或维修 |

#### 4.10.3 扣分因素

- 严重故障码。

- 重复故障。
- 未关闭工单。
- 近 30/90 天故障频次。
- 运行小时和维护风险。

评分必须展示扣分原因。

## 五、状态规格

### 5.1 故障上报单状态

AI待提交 -> 待接单 -> 维修中 -> 已处理。

说明：AI待提交仅适用于运维Agent生成但尚未由用户在故障上报页面正式提交的单据。用户提交后状态变为待接单，故障编号保持不变。

### 5.2 工单状态

草稿 -> 待接单 -> 维修中 -> 待验收 -> 已完成。

异常流转：

- 草稿 -> 已撤回。
- 待验收 -> 返修中 -> 维修中。
- 草稿/待接单 -> 已驳回。

### 5.3 知识文档状态

待上传 -> 上传中 -> 待解析 -> 解析中 -> 切片中 -> 索引中 -> 已就绪。  
待解析/解析中 -> 解析失败。  
切片中/索引中 -> 索引失败。  
已就绪 -> 已停用。

### 5.4 历史案例状态

待审核 -> 已入库。  
待审核 -> 已驳回。  
已入库 -> 已停用。

## 六、异常处理规格

| 场景 | 处理方式 |
|---|---|
| 必填信息缺失 | 禁止提交，提示缺失项 |
| 用户无故障上报功能权限 | AI故障上报可对话和预览，但不允许创建 AI待提交 单据 |
| 用户无 AI 悬浮框权限 | 不展示或不允许打开运维Agent入口 |
| 智能问数 API 失败或超时 | 提示本次查询未成功，保留上一轮成功结果并提供重试 |
| 导入设备编号不存在 | 记录失败行和失败原因 |
| 参数编码不匹配 | 记录失败或提示字段未匹配 |
| 知识文档解析失败 | 状态置为解析失败，不进入 Agent 知识范围 |
| RAGFlow 上传失败 | 软件系统提示上传失败，允许重新上传 |
| RAGFlow 切片或索引失败 | 状态置为索引失败，不进入 Agent 知识范围 |
| RAGFlow 检索超时或不可用 | Agent 提示知识检索暂不可用，并要求人工复核或稍后重试 |
| LangGraph Agent 服务不可用 | 软件系统提示智能服务暂不可用，保留人工表单和人工工单流程 |
| 诊断置信度低 | 标记需人工复核 |
| 高风险系统故障 | 优先提示停机、安全检查和人工复核 |

## 七、验收规格摘要

- 设备台账可新增、编辑、筛选和查看，设备编号唯一。
- AI 悬浮框权限、故障上报功能权限可在系统管理的用户管理和角色管理中配置。
- 设备知识配置支持 BOM、额定参数、知识文档、故障知识、历史案例五个 Tab。
- 额定参数支持自定义扩充，参数编码可匹配导入数据字段。
- 知识文档可从软件系统上传至 RAGFlow，并展示上传、解析、切片、索引和失败状态。
- Agent 必须通过 LangGraph 框架实现，不能以纯代码规则判断替代。
- Agent 可调用 RAGFlow 检索知识，并展示引用来源。
- 人工表单可直接提交故障上报单；AI故障上报生成 AI待提交 单据，由用户在故障上报页面正式提交。
- 关键信息缺失时不允许生成 AI故障上报结构化预览或提交故障上报。
- AI故障上报创建 AI待提交 单据前必须校验故障上报功能权限。
- 智能问数不做数据权限校验。
- 数据导入可输出成功和失败结果。
- Agent 诊断必须展示依据、置信度和风险等级。
- 维修建议必须包含排查步骤、维修步骤、安全注意事项、工具/备件、工时/成本。
- 草稿工单必须人工确认后派发。
- 工单关闭后生成历史案例或待审核知识。
- 健康评分展示分数、等级、扣分原因。
- 驾驶舱 BI 展示核心故障运维指标。
- 运维Agent支持 AI故障上报、智能问数、操作指引三个独立历史 Tab。
- 用户及权限管理支持角色、权限和操作日志；设备负责人在设备台账新增或编辑设备时选择。
