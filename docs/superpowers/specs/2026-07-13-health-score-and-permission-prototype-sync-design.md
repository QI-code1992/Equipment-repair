# 健康分与权限原型同步设计

日期：2026-07-13  
状态：已确认，待实施

## 目标

将静态原型中的健康分展示统一为同一个原型健康分服务，并补齐系统管理的全菜单、全操作权限目录。

## 范围

### 健康分

- 新增公共原型适配层 `assets/health-score-service.js`。
- 适配层集中维护设备当前健康分快照和风险等级映射；页面不得各自维护同一设备的健康分。
- 设备详情、设备台账、工作台、驾驶舱 BI 统一通过适配层读取当前健康分。
- 原型适配层模拟正式版健康分服务；正式开发时以真实健康分 API 替换，不改变页面的读取边界。
- 风险等级固定为：100 正常；80–99 低风险；60–79 中风险；40–59 高风险；0–39 严重风险。
- 设备详情链接携带 `device` 参数，并按该参数读取设备健康分快照。
- BI 的日期筛选仅影响故障、维修等历史数据；不影响当前健康分和当前风险等级。

### 系统管理权限

- 工厂建模继续用于定义设备所属工厂、车间、产线和位置；不承担用户数据范围划分。
- 系统管理组织继续用于账号归属；不增加数据权限字段、组织范围过滤或 Agent 数据范围过滤。
- 基础角色固定为：系统管理员、设备管理员、维修工、产线作业员。
- 权限目录覆盖八个当前菜单及其对应操作：工作台、驾驶舱 BI、工厂建模、设备台账、故障上报、维修记录、系统管理、智能配置。

### 数据导入

- 数据导入不是一期开发项。
- 保留历史 `data-import.html` 文件，不删除、不修改为当前功能，也不从任何当前入口访问。
- 从当前导航、权限目录、需求基线和开发计划中移除“数据导入”。
- 所有初始业务数据按既定结论手动录入。

## 原型修正规则

- 删除或修正 BI 中“健康分低于 60 自动生成工单”的表达。
- 健康分布分开显示高风险与严重风险，不再合并为“高/严重风险”。
- 工作台健康统计改用统一健康分服务结果，不自行维护独立健康分样例。
- 设备详情、设备台账、工作台、BI 中相同设备编号必须展示同一健康分快照和风险等级。
- 本次不调整健康分业务扣分、恢复、快照规则；只同步既有确认口径的展示与原型读取方式。

## 验收

1. 同一设备在上述四类页面的健康分和风险等级一致。
2. 设备详情可随 `device` 参数展示对应设备信息与健康分快照。
3. 工作台和 BI 的风险分布使用五档规则。
4. 系统管理权限编辑器可见八个当前菜单的权限组。
5. 系统管理角色列表只保留四个基础角色。
6. 既有原型健康分相关检查与新增一致性检查均通过。

## 非目标

- 不实现真实后端、登录、数据库、RAGFlow 或 LangGraph 服务。
- 不增加数据权限。
- 不修改工厂建模的设备层级功能。
- 不删除历史数据导入页面文件。
