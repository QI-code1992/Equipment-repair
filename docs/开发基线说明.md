# 开发基线说明

## 唯一有效依据

在最终 PRD、开发 SPEC、接口契约和验收标准完成前，本项目不得开始正式业务开发。完成后，开发人员只能以这四份文件为准，不得从旧计划、静态示例、聊天记录或页面文案推断业务规则。

当前已确认规则的汇总来源为：

- `PRD-当前有效版.md`
- `今日对接结论.md`

后续将把两份文件合并为正式的最终 PRD，并补充开发 SPEC、接口契约与验收标准。

## 历史材料使用规则

以下材料仅保留追溯价值，禁止作为开发、测试或验收依据：

- `superpowers/plans/2026-07-13-health-score-prototype-sync.md`
- 原型中的静态演示分数、旧风险等级、旧状态名称和旧恢复文案
- 未明确标注为“当前有效”的历史说明

若历史材料与当前有效规则冲突，以当前有效规则为准；发现未收录的新冲突时，必须停止受影响功能开发并提交产品澄清。

## 已替换规则清单

| 原规则/展示 | 当前有效规则 |
|---|---|
| 上线回算最近 30 天历史数据 | 正式上线日所有设备从 100 分开始，不回算上线前数据 |
| 80–100 正常、60–79 关注、0–59 低健康 | 100 正常、80–99 低风险、60–79 中风险、40–59 高风险、0–39 严重风险 |
| 逾期发生后滚动 30 天自动恢复 | 未处理持续保留；已处理后第 30 个自然日 00:00 恢复 |
| SLA 从接单开始 | SLA 从故障单正式提交开始，到已处理结束 |
| 可重新打开已处理故障单 | 一期仅待接单、维修中、已处理三种状态，不支持重新打开 |
| 待接单故障可由任意有按钮权限人员删除 | 仅提交人可删除待接单故障单，无需填写删除原因，后台保留审计日志 |
| 停用设备可与未关闭故障共存 | 存在待接单或维修中故障时禁止停用设备 |

## 原型修订原则

原型修订必须基于最终 PRD/SPEC 执行。任何页面不得自行计算健康分；工作台、BI、台账、设备详情和智能问数统一使用健康分服务结果。
