## 二、产品概述

### 2.1 产品背景

新能源装载机在矿山、港口、园区、砂石料场、基建工地等场景中的使用比例持续提升。相比传统燃油装载机，新能源装载机增加了电池、电机、电控、热管理、充电等关键系统，故障判断更依赖数据、故障码、维修手册和经验积累。

设备使用方在日常运维中通常面临以下问题：

- 故障上报信息不完整，维修人员需要反复沟通确认。
- 故障码、报警记录、运行数据、维修经验分散，无法快速形成判断。
- 维修建议依赖少数资深人员，标准化程度不足。
- 维修完成后的经验没有沉淀，类似故障重复排查。
- 管理层缺少对设备健康状态和待处理故障的直观判断。

### 2.2 产品定位

本产品定位为面向新能源装载机设备使用方的设备故障智能运维平台，聚焦故障处理闭环：

故障上报和数据导入 -> Agent 智能诊断 -> 专家级维修建议 -> 草稿工单 -> 人工确认派发 -> 维修执行 -> 维修记录沉淀 -> 设备健康评分更新。

### 2.3 业务目标

- 缩短从故障发现到维修响应的时间。
- 提升故障诊断和维修建议的标准化程度。
- 降低对个别资深维修人员经验的依赖。
- 建立新能源装载机设备知识底座，支撑持续诊断优化。
- 通过设备健康评分识别高风险设备，辅助管理层决策。

### 2.4 MVP 范围

MVP 包含以下能力：

- 设备台账管理。
- 设备知识配置，包括 BOM 组成、额定参数、知识文档、故障知识、历史案例。
- RAGFlow 知识库集成，用于知识文档解析、切片、向量化、索引、检索和引用来源返回。
- 人工表单故障上报。
- 全局运维Agent，包括 AI故障上报、智能问数、操作指引三个子 Tab。
- Agent 对话式故障上报，生成故障上报页的 AI待提交单据。
- Agent 功能权限识别，包括 AI 悬浮框权限和故障上报功能权限。
- 基于 LangGraph 的 Agent 流程编排。
- 故障码、报警记录、运行数据的 Excel/CSV 导入。
- Agent 智能诊断。
- 专家级维修建议。
- 草稿维修工单与人工确认派发。
- 维修执行与维修记录沉淀。
- 设备健康评分。
- 简单驾驶舱 BI。
- 基础系统用户及权限管理。

### 2.5 非目标

以下内容不纳入 MVP：

- 场站、车队、施工项目等组织层级管理。
- 移动端、小程序、H5 独立端。
- 实时车联网、T-BOX、控制器平台直接接入。
- 完整备件库存、采购、出入库管理。
- 厂家售后结算、质保索赔和服务商管理。
- 充电站运营管理。
- AR 维修、远程视频协作。
- 数字孪生和 3D 可视化。
- 复杂预测性维护模型。
- 复杂自定义 BI 报表平台。
- 从零自研 RAG 文档解析、切片、向量库和检索管理平台。
- 使用 RAGFlow 内置工作流替代 LangGraph Agent 流程编排。
- 用纯业务代码规则判断替代 LangGraph Agent。

### 2.6 正式架构原则

本产品正式架构采用三模块分工：

| 模块 | 职责 |
|---|---|
| 软件系统 | 承载业务流程、用户界面、权限、设备台账、故障上报、工单、维修记录、健康评分、知识上传入口和结果展示 |
| LangGraph Agent | 承载智能体流程编排、意图识别、权限校验、缺失信息追问、RAG 检索调用、诊断生成、维修建议和草稿工单建议 |
| RAGFlow | 承载 RAG 知识库能力，包括文档解析、切片、向量化、索引、检索、引用来源和文档处理状态 |

核心原则：

- RAGFlow 保留为正式 RAG 知识库底座。
- Agent 流程统一由 LangGraph 实现，用 LangGraph 管理多节点状态流转。
- RAGFlow 不直接负责业务 Agent 编排。
- LangGraph Agent 不重复建设文档切片、向量索引和知识库管理能力。
- 软件系统不直接拼接 Prompt 进行诊断，只调用 LangGraph Agent 服务并展示结构化结果。
- Agent 需要调用 RAGFlow 检索结果，也需要调用软件系统中的设备、权限、工单、维修记录、健康评分和问数 API 等业务数据。

## 四、核心业务流程

### 4.1 人工表单故障上报流程

1. 用户进入故障上报页面。
2. 选择设备。
3. 填写故障现象、紧急程度、发生时间、可能故障位置、故障说明。
4. 可选上传照片或视频。
5. 系统校验必填信息。
6. 必填信息完整后提交故障上报单。
7. 系统触发 Agent 智能诊断。

### 4.2 运维Agent辅助故障上报流程

1. 用户打开右下角运维Agent，进入 AI故障上报 Tab。
2. Agent 根据用户是否具备故障上报功能权限，提示可生成 AI待提交 单据或仅可咨询整理。
3. 用户通过设备选择器选择一台设备。
4. Agent 追问并收集故障现象、紧急程度、发生时间、可能故障位置、现场图片、日志或视频附件。
5. Agent 可追加最多 5 轮辅助追问，并将额外信息整理为故障说明。
6. 满足预览条件后，Agent 提示可生成结构化预览，并说明非必填缺失项。
7. 用户查看只读结构化预览；如需修改，通过继续对话让 Agent 调整。
8. 用户确认后生成状态为 AI待提交 的故障上报单，系统分配正式故障编号。
9. 用户可选择前往故障上报页面，在列表中对 AI待提交 单据执行详情、编辑、提交或删除。
10. 用户在故障上报页面提交后，单据状态变为待接单。

### 4.3 数据导入诊断流程

1. 设备管理员进入数据导入页面。
2. 选择导入类型：故障码、报警记录、运行数据。
3. 上传 Excel/CSV 文件。
4. 系统校验设备编号、字段格式、时间格式、参数编码和数据范围。
5. 校验通过的数据入库，并生成导入日志。
6. 系统结合导入数据触发或补充 Agent 诊断。

### 4.4 草稿工单流转

1. Agent 根据故障上报单、导入数据和知识底座生成诊断结果。
2. Agent 生成专家级维修建议。
3. 系统生成草稿维修工单。
4. 设备管理员查看草稿工单，可确认、修改、撤回。
5. 设备管理员派发给维修人员。
6. 维修人员接单并执行维修。
7. 维修完成后提交维修记录。
8. 设备管理员验收或关闭工单。

### 4.5 知识沉淀流程

1. 维修人员提交维修记录。
2. 系统提取故障现象、故障原因、处理方案、备件、工时、成本和照片。
3. 系统关联设备、设备型号、BOM 节点和故障知识。
4. 如匹配已有故障知识，追加为历史案例。
5. 如无法匹配，标记为新故障模式，等待设备管理员审核。

## 五、功能需求

### 5.1 设备台账

#### 5.1.1 功能说明

设备台账用于维护新能源装载机基础档案，是故障上报、诊断、工单和健康评分的基础。

#### 5.1.2 核心字段

| 字段 | 说明 | 必填 |
|---|---|---|
| 设备编号 | 设备唯一标识 | 是 |
| 设备名称 | 设备展示名称 | 是 |
| 设备型号 | 新能源装载机型号 | 是 |
| 设备类型 | 装载机/其他扩展类型 | 是 |
| 生产厂家 | 设备制造商 | 否 |
| 出厂日期 | 设备出厂日期 | 否 |
| 投入使用日期 | 设备投入使用日期 | 否 |
| 运行小时 | 设备累计运行小时 | 否 |
| 设备状态 | 正常、故障、维修中、停用 | 是 |
| 设备负责人 | 负责该设备的管理人员 | 否 |
| 设备图片 | 设备照片 | 否 |

#### 5.1.3 业务规则

- 设备编号必须唯一。
- 设备负责人用于设备台账管理和业务责任展示。
- 运维Agent智能问数不按设备负责人做数据权限过滤。
- 设备删除前，如存在未关闭故障上报单或维修工单，应禁止删除。
- 设备状态可由人工维护，也可由故障单、维修工单状态联动更新。
- 设备台账不包含场站管理。

### 5.2 设备知识与自动知识图谱

#### 5.2.1 功能说明

设备知识能力合并到设备台账中，不再作为独立侧边导航功能。新增或编辑设备时，沿用现有设备基础信息、设备负责人、额定参数、BOM、知识文档、故障知识和历史案例内容，并新增“知识图谱”能力。

知识图谱不要求人工手动搭建。人工只需上传与设备相关的知识资料，系统自动解析额定参数、BOM 组成、知识文档、故障知识和历史案例，抽取实体、关系、依据来源，并自动生成设备知识图谱。管理员可查看解析结果、补充资料、审核异常关系，但默认不需要人工拖拽构建图谱。

设备详情页应提供以下 Tab：

- 概览。
- BOM 组成。
- 额定参数。
- 知识文档。
- 故障知识。
- 历史案例。
- 知识图谱。

#### 5.2.2 BOM 组成

BOM 用于描述新能源装载机结构组成，建议层级为：

整机 -> 系统 -> 总成/模块 -> 部件 -> 零件。

典型系统包括：

- 电池系统。
- 电机系统。
- 电控系统。
- 液压系统。
- 传动系统。
- 制动系统。
- 热管理系统。
- 充电系统。
- 驾驶室与电气附件。

业务规则：

- BOM 支持按设备型号维护和复用。
- BOM 节点可关联额定参数、知识文档、故障知识和历史案例。
- BOM 可通过上传 BOM 清单自动解析生成，管理员可审核和修正解析结果。
- BOM 缺失时，Agent 可继续诊断，但应提示“未关联 BOM，部件定位可信度降低”。

#### 5.2.3 额定参数

额定参数用于定义设备或 BOM 节点的标准运行范围，支持自定义扩充。

核心字段：

| 字段 | 说明 | 必填 |
|---|---|---|
| 参数名称 | 如电池温度、电机温度、液压压力 | 是 |
| 参数编码 | 用于匹配导入数据字段 | 是 |
| 单位 | 如 ℃、V、A、MPa、h | 否 |
| 标准值 | 参数正常参考值 | 否 |
| 下限 | 低于该值触发异常判断 | 否 |
| 上限 | 高于该值触发异常判断 | 否 |
| 告警等级 | 提示、警告、紧急 | 是 |
| 关联 BOM 节点 | 参数所属系统、模块或部件 | 否 |
| 适用设备型号 | 参数适用范围 | 是 |

业务规则：

- 管理员可新增、编辑、停用额定参数。
- 额定参数可通过上传参数表自动解析生成，解析结果需展示来源文件与解析状态。
- 参数编码必须支持与 Excel/CSV 导入字段匹配。
- 同一设备型号下参数编码不允许重复。
- 参数超出上下限时，Agent 诊断和健康评分应可引用该异常。
- 参数未设置上下限时，不参与阈值异常判断，但可作为诊断上下文。

#### 5.2.4 知识文档

知识文档用于支撑 Agent 检索、维修建议和知识问答。知识文档由软件系统提供上传和管理入口，正式解析、切片、向量化、索引和检索能力由 RAGFlow 承载。

文档类型包括：

- 设备说明书。
- 维修手册。
- 故障码手册。
- 电气原理图。
- 液压原理图。
- 保养手册。
- 安全操作规范。
- 培训资料。
- 历史故障案例集。
- 厂家服务通告。

业务规则：

- 文档可关联设备型号、系统、BOM 节点。
- 文档状态包括待解析、已就绪、解析失败、已停用。
- Agent 输出维修建议时，应尽量引用知识文档来源。
- 解析失败的文档不得进入 Agent 可用知识范围。
- 文档解析成功后，系统应自动抽取可用于知识图谱的实体、故障现象、部件关系和维修依据。
- 软件系统应向 RAGFlow 传输文档文件和必要 metadata，并展示 RAGFlow 返回的解析、切片和索引状态。
- LangGraph Agent 检索知识时，应通过 RAGFlow 获取相关片段、来源、相似度和文档 metadata。
- RAGFlow 返回的知识片段不直接作为最终诊断结论，必须经 LangGraph Agent 结合故障上下文和业务数据后形成结构化输出。

#### 5.2.5 故障知识与历史案例

故障知识用于维护常见故障码、故障现象、可能原因、处理建议和安全注意事项。历史案例来自维修记录沉淀。

业务规则：

- 故障知识可由文档、故障知识库文件和历史案例自动抽取生成，管理员可审核和修正。
- 维修记录关闭后可自动生成历史案例。
- 新故障模式应进入待审核状态，审核后才能作为正式故障知识。
- 历史案例可从关闭工单自动沉淀，也可通过批量上传历史案例文件导入。
- 知识图谱应把故障知识、历史案例、BOM 节点、额定参数和知识文档来源关联起来，并支持在诊断、维修建议中引用。

### 5.3 故障上报

#### 5.3.1 功能说明

系统支持人工表单上报和运维Agent辅助上报两个入口。人工表单上报由用户在故障上报页面直接填写并提交；运维Agent辅助上报由用户在全局右下角运维Agent的“AI故障上报”Tab中通过对话生成故障上报页面的 AI待提交 单据。

AI待提交单据不是正式提交动作。用户必须进入故障上报页面，对该单据执行编辑、提交或删除。提交成功后，该单据状态变为待接单，并进入现有故障处理流转。

#### 5.3.2 故障上报字段

故障上报字段应与故障上报新增页保持一致。

| 字段 | 必填 | 说明 |
|---|---|---|
| 选择设备 | 是 | 选择本次上报故障的设备，每次只能上报一台设备 |
| 所属车间 | 否 | 选择设备后自动带出 |
| 所属产线 | 否 | 选择设备后自动带出 |
| 紧急程度 | 是 | 非常紧急、紧急、一般；Agent 场景未选择时可默认紧急，并提示用户可修改 |
| 故障现象 | 是 | 描述设备异常表现 |
| 发生时间 | 否 | 故障发生或发现时间 |
| 可能故障位置 | 否 | 例如驱动电机、电池包 3 号模组、充电接口 |
| 故障说明 | 否 | 最佳填报标准为“现象 + 条件 + 影响 + 已做的临时处置” |
| 现场图片 | 否 | 仪表照片、现场图片等 |
| 日志或视频附件 | 否 | 日志、视频或其他辅助附件 |

#### 5.3.3 AI待提交状态

- AI故障上报生成的单据状态为 AI待提交。
- AI待提交单据使用正式故障编号，例如 `FR-20260701-001`。
- AI待提交单据在故障上报页面列表中支持详情、编辑、提交、删除。
- 用户提交 AI待提交 单据后，故障编号不变，状态变为待接单。
- AI待提交单据不设置有效期，不自动删除，不做过期提醒。
- AI待提交单据正式提交后按普通故障上报单处理，不额外展示“来源：运维Agent”。

#### 5.3.4 运维Agent辅助上报规则

- 用户进入 AI故障上报 Tab 后，Agent 首句提示：`我可以帮你通过对话生成待提交故障单。请先选择设备。`
- 设备必须通过设备选择器选择，选择器展示设备编号、设备名称、所属车间、所属产线；一次只能选择一台设备。
- Agent 按故障上报字段追问设备、故障现象、紧急程度、发生时间、可能故障位置、现场图片、日志或视频附件。
- 设备和故障现象是生成预览的关键字段；紧急程度若用户未选择，Agent 可默认紧急，并在预览中标注可在故障上报页修改。
- Agent 可追加追问辅助信息，但额外追问最多 5 轮；额外信息最终归纳进故障说明。
- 现场图片、日志和视频附件通过统一附件入口上传，预览时按现场图片、日志或视频附件分组展示。
- 当前版本不识别图片内容，不自动提取故障码或仪表信息；如图片中包含重要报警码，Agent 可提醒用户用文字补充。
- 当满足生成预览条件后，Agent 主动询问是否生成结构化预览，并提示哪些非必填项尚未补充。
- 结构化预览为只读，预览中的所有信息不可直接编辑；需要调整时，用户应通过继续对话让 Agent 修改。
- 结构化预览底部操作为生成待提交单、继续对话、取消。
- 生成成功后不自动跳转，只在对话中提示已生成 AI待提交故障单并提供“去故障上报页查看”入口。
- 若当前用户有 AI 悬浮框权限但无故障上报功能权限，进入 AI故障上报 Tab 时 Agent 应以对话形式提示用户可咨询和整理信息，但无法创建 AI待提交 单据。

### 5.4 全局运维Agent

#### 5.4.1 功能定位

运维Agent是全局右下角悬浮入口，提供 AI故障上报、智能问数、操作指引三个子 Tab。运维Agent是辅助工具，不替代用户在业务页面上的最终确认动作。

#### 5.4.2 入口与面板交互

- 悬浮入口名称为运维Agent，可简短显示 Agent。
- 悬浮入口可拖拽位置，拖拽结束后自动吸附到页面右侧。
- 3 秒未点击、未悬停、未拖拽时，悬浮入口变为半透明；交互时恢复不透明。
- 点击悬浮入口后打开右侧抽屉，抽屉打开时悬浮入口不可见。
- 抽屉不加全屏遮罩，允许用户继续操作底层页面。
- 抽屉宽度按桌面 Web 中版设计，约 560-640px；本阶段不要求移动端适配。
- 顶部标题为运维Agent，仅保留清除当前 Tab 对话和关闭两个控制。
- 关闭抽屉不清除对话；清除对话只清除当前 Tab 历史。
- 首次打开默认进入 AI故障上报；之后再次打开回到上次关闭时所在 Tab。
- 三个 Tab 的对话历史相互独立，页面跳转后历史不清除。
- 正常情况下不显示服务状态；仅在 Agent 服务、问数 API、附件上传等异常时提示。
- 视觉风格应融合当前后台系统风格和参考助手面板风格，头部与 Tab 可有更明显的智能助手识别度。

#### 5.4.3 权限边界

- 权限控制到 AI 悬浮框总入口，不控制到三个 Tab。
- 具有 AI 悬浮框权限的用户可以进入 AI故障上报、智能问数、操作指引三个 Tab。
- AI 悬浮框权限、故障上报功能权限来自系统管理中的用户管理和角色管理。
- 智能问数不做数据权限校验，用户可问全局业务数据。
- 操作指引不做 Tab 级权限限制。
- AI故障上报能否创建 AI待提交 单据取决于用户是否具备故障上报功能权限。

#### 5.4.4 智能问数

- 智能问数支持全局业务数据问询，不限定当前页面。
- 查询范围包括设备台账、故障上报、维修记录、工单或维修进度、设备健康评分、驾驶舱 BI 指标、数据导入结果等。
- 智能问数需要调用后台 API 获取数据，不使用静态假数据作为正式结果。
- 用户信息不足时，Agent 应根据问题主动追问关键条件；可合理默认时先回答并说明口径。
- 默认时间范围为近30天，用户可通过对话修改为近7天、近三个月、自定义日期等。
- 支持多轮继承查询条件并重算结果，例如追加故障类型、设备范围、时间范围等过滤条件。
- 回答形式支持文字结论、指标卡片、图表、明细表、Top 排行和分布图。
- 支持带筛选条件下钻跳转到设备详情、故障上报、维修记录、驾驶舱等页面。
- 支持复制结果、导出 Excel、生成可复制或下载的文本报告摘要。
- API 查询失败或超时时，应提示本次查询未成功，保留上一次成功结果，并说明当前展示结果未按本次条件更新。

#### 5.4.5 操作指引

- 操作指引支持当前页面帮助、跨页面流程指引、报错原因解释、权限或限制说明。
- 操作指引 Tab 显示当前页面上下文；AI故障上报和智能问数不显示当前页面上下文。
- Agent 在未理解用户需求前，不应直接引导用户跳转。
- 操作指引默认给简短回答，用户可展开详细步骤。
- 当回答包含步骤时，支持复制步骤。
- 操作指引可提供跳转入口，但不自动跳转，不做页面元素高亮。

#### 5.4.6 输入与快捷问题

- 三个 Tab 使用统一输入栏，包括附件按钮、文本输入框、发送按钮。
- 输入栏 placeholder 和附件用途随当前 Tab 变化。
- AI故障上报用于描述故障、补充字段、上传现场图片、日志或视频。
- 智能问数用于输入数据问题，可上传文件作为补充条件。
- 操作指引用于询问步骤、字段、报错，可上传截图辅助说明。
- 每个 Tab 空历史时显示固定快捷问题；一旦该 Tab 有对话历史，快捷问题隐藏或弱化。
- 清除当前 Tab 对话后，该 Tab 的快捷问题重新出现。

### 5.5 数据导入

#### 5.5.1 功能说明

数据导入用于将故障码、报警记录和运行数据导入系统，支撑 Agent 诊断、健康评分和维修建议。

#### 5.5.2 导入类型

| 类型 | 说明 |
|---|---|
| 故障码数据 | 设备故障码、故障时间、故障等级、故障描述 |
| 报警记录 | 设备报警、报警时间、报警等级、报警内容 |
| 运行数据 | 参数编码、参数值、采集时间、设备编号 |

#### 5.5.3 业务规则

- 支持 Excel/CSV 导入。
- 系统应校验设备编号是否存在。
- 系统应校验时间格式、字段格式、参数编码和必填字段。
- 导入失败的数据应生成失败原因。
- 导入成功后，应生成导入日志。
- 导入数据可触发 Agent 诊断或补充既有诊断依据。

### 5.6 Agent 智能诊断

#### 5.6.1 功能说明

Agent 根据故障上报单、导入数据、BOM、额定参数、知识文档、故障知识和历史案例，输出结构化诊断结果。

#### 5.6.2 输出内容

- 故障类型。
- 风险等级。
- 是否建议停机。
- 可能原因排序。
- 每个可能原因的置信度。
- 关联 BOM 节点。
- 异常参数和故障码。
- 诊断依据来源。
- 需人工复核提示。

#### 5.6.3 业务规则

- Agent 诊断结果必须展示依据来源。
- Agent 展示诊断结果前必须校验用户是否有权查看对应设备。
- 低置信度诊断必须标记“需人工复核”。
- 高压电池、电控、制动、液压等安全风险场景，应优先输出停机和安全检查建议。
- Agent 不能直接派发维修工单。
- 当知识库或数据不足时，应明确说明不足项。

### 5.7 专家级维修建议

#### 5.7.1 功能说明

系统基于诊断结果生成专家级维修建议，辅助维修人员执行排查和维修。

#### 5.7.2 输出内容

- 分步骤排查流程。
- 分步骤维修方案。
- 所需工具。
- 所需备件。
- 安全注意事项。
- 相似历史案例。
- 预计工时。
- 预计成本。
- 参考知识来源。

#### 5.7.3 业务规则

- 维修建议必须与诊断结果关联。
- 展示维修建议前必须校验用户是否有权查看对应设备。
- 无历史案例时，应优先引用知识文档和故障知识，并标注“暂无相似历史案例”。
- 预计工时和成本可基于历史案例或人工配置，不足时允许显示“待人工评估”。

### 5.8 草稿维修工单

#### 5.8.1 功能说明

系统根据诊断结果和维修建议生成草稿维修工单，由设备管理员人工确认后派发。

#### 5.8.2 核心字段

| 字段 | 说明 |
|---|---|
| 工单编号 | 系统生成 |
| 来源故障单 | 关联故障上报单 |
| 设备 | 关联设备 |
| 故障摘要 | Agent 或管理员整理 |
| 风险等级 | 来自诊断结果 |
| 建议处理方案 | 来自维修建议 |
| 建议备件 | 来自维修建议 |
| 建议工时 | 来自维修建议 |
| 指派维修人员 | 设备管理员确认 |
| 工单状态 | 草稿、待接单、维修中、待验收、已完成、已撤回 |

#### 5.8.3 业务规则

- Agent 只能生成草稿工单。
- 草稿工单必须经设备管理员确认后才能派发。
- 设备管理员可修改草稿工单内容。
- 草稿工单可撤回。

### 5.9 维修执行与记录沉淀

#### 5.9.1 功能说明

维修人员接收工单后执行维修，并提交结构化维修记录。维修记录用于知识沉淀和后续诊断。

#### 5.9.2 维修记录内容

- 实际故障原因。
- 实际处理方案。
- 使用备件。
- 实际工时。
- 实际成本。
- 维修照片。
- 维修结果。
- 是否复发或需复检。

#### 5.9.3 业务规则

- 未填写实际故障原因和处理方案时，不允许关闭工单。
- 维修完成后可进入待验收状态。
- 工单关闭后，系统应生成历史案例或待审核知识条目。

### 5.10 设备健康评分

#### 5.10.1 功能说明

设备健康评分用于展示设备当前风险状态，辅助设备管理员和管理层识别高风险设备。

#### 5.10.2 评分展示

- 健康分：0-100 分。
- 健康等级：健康、关注、风险、高风险。
- 扣分原因。
- 最近趋势。
- 关联故障、报警、工单。

#### 5.10.3 评分规则

MVP 采用可解释规则，不使用黑盒复杂预测模型。

评分依据包括：

- 故障码严重程度。
- 参数异常次数、持续时间和严重程度。
- 近 30/90 天故障频次。
- 重复故障。
- 未关闭工单。
- 运行小时和维护风险。
- 维修关闭和稳定运行恢复情况。

业务规则：

- 健康评分必须展示扣分原因。
- 数据不足时应显示评分可信度或提示“数据不足，评分仅供参考”。
- 健康评分应在设备详情和驾驶舱 BI 中展示。

### 5.11 驾驶舱 BI

#### 5.11.1 功能说明

驾驶舱 BI 提供简单的故障运维概览，不做复杂自定义报表平台。

#### 5.11.2 指标范围

- 设备总数。
- 故障设备数。
- 待处理工单数。
- 本月故障次数。
- 平均维修时长。
- 设备健康评分分布。
- 高风险设备 Top 5。
- 故障类型分布。
- 近期告警/故障趋势。
- 工单状态分布。

#### 5.11.3 业务规则

- 管理层、系统管理员、设备管理员可查看驾驶舱。
- 维修人员可查看与本人相关的工单统计。
- 驾驶舱指标应支持按时间范围筛选。

### 5.12 系统用户及权限管理

#### 5.12.1 功能说明

系统用户及权限管理用于维护账号、角色、权限和操作日志。设备负责人在设备台账新增或编辑设备时选择。

#### 5.12.2 功能范围

- 登录/退出。
- 用户管理。
- 角色管理。
- 权限配置。
- 账号启用/停用。
- 密码重置。
- 用户可访问设备范围配置。
- 操作日志。

#### 5.12.3 业务规则

- 系统管理员可管理全部用户和角色。
- 账号停用后不得登录。
- 系统管理中的用户管理和角色管理应支持 AI 悬浮框权限和故障上报功能权限配置。
- AI 悬浮框权限控制用户是否可使用运维Agent总入口；故障上报功能权限控制用户是否可由 AI故障上报生成 AI待提交 单据。
- 关键操作应记录操作日志，包括数据导入、知识配置变更、工单派发、工单关闭。

## 六、Agent 能力边界与输出规范

### 6.1 能力边界

- Agent 可辅助故障上报、智能问数、操作指引、诊断、维修建议和草稿工单生成。
- Agent 必须基于 LangGraph 框架开发，不能以纯业务代码规则判断替代智能体流程。
- Agent 应使用 LangGraph 对意图识别、功能权限校验、缺失信息追问、RAGFlow 检索、业务数据查询、问数 API 调用、诊断生成、维修建议和人工确认等节点进行编排。
- Agent 可调用 RAGFlow 进行知识检索，但不负责文档切片、向量化、索引和知识库管理。
- Agent 必须自动识别当前登录用户的角色和功能权限。
- Agent 不可直接派发工单。
- Agent 不可替代维修人员的最终安全判断。
- Agent 不可在缺失必填故障上报信息时强行提交故障单。
- Agent 不可在用户无故障上报功能权限时创建 AI待提交 单据。
- Agent 不可在无依据情况下输出确定性结论。

### 6.2 输出规范

Agent 输出应包含：

- 结论。
- 置信度。
- 依据来源。
- 风险提示。
- 建议动作。
- 需人工复核的情况。

### 6.3 安全要求

涉及高压电池、电控、制动、液压、热管理等高风险系统时，Agent 应优先输出安全提示，并建议停机检查或人工复核。

## 七、数据需求

### 7.1 核心数据对象

| 数据对象 | 说明 |
|---|---|
| 用户 | 系统账号、角色、权限 |
| 设备 | 新能源装载机台账 |
| 设备知识配置 | BOM、额定参数、知识文档、故障知识、历史案例 |
| RAGFlow 知识文档记录 | 软件系统与 RAGFlow 文档、数据集、解析状态、切片状态和索引状态的映射关系 |
| RAG 检索引用 | RAGFlow 返回的知识片段、来源文档、相似度、页码或位置、metadata |
| 故障上报单 | 人工创建或运维Agent生成 AI待提交 后由用户提交的故障信息 |
| 运维Agent会话 | 三个 Tab 独立对话历史、当前 Tab、上次打开位置、问数上下文和 AI故障上报收集状态 |
| 导入记录 | 故障码、报警、运行数据导入日志 |
| 诊断结果 | Agent 输出的结构化诊断 |
| 维修建议 | Agent 输出的专家级维修建议 |
| 维修工单 | 草稿、派发、执行、验收和关闭 |
| 维修记录 | 实际维修过程和结果 |
| 健康评分 | 设备健康分、等级、扣分原因 |
| 操作日志 | 关键操作审计记录 |

### 7.2 数据来源

- 用户录入：设备、故障上报、维修记录、知识配置。
- 文件导入：故障码、报警记录、运行数据。
- RAGFlow：知识文档解析结果、切片状态、检索片段和引用来源。
- 系统生成：诊断结果、维修建议、草稿工单、健康评分、操作日志。
- 知识沉淀：维修记录自动生成历史案例和待审核知识条目。

## 九、状态流转与权限规则

### 9.1 工单状态

草稿 -> 待接单 -> 维修中 -> 待验收 -> 已完成。

异常状态包括：

- 已撤回。
- 已驳回。
- 返修中。

### 9.2 知识文档状态

待解析 -> 已就绪。  
待解析 -> 解析失败。  
已就绪 -> 已停用。

### 9.3 故障上报单状态

AI待提交 -> 待接单 -> 维修中 -> 已处理。

### 9.4 设备健康等级

| 分数 | 等级 | 说明 |
|---|---|---|
| 85-100 | 健康 | 当前风险较低 |
| 70-84 | 关注 | 存在轻微异常或维护风险 |
| 50-69 | 风险 | 存在明显故障或重复异常 |
| 0-49 | 高风险 | 建议优先停机检查或维修 |

## 十、非功能需求

### 10.1 性能

- 设备列表、工单列表、故障单列表应支持分页和筛选。
- 常规列表查询应在可接受时间内返回结果。
- 单次 Excel/CSV 导入应支持常见批量运维数据规模，并提供导入进度和结果反馈。

### 10.2 安全

- 用户必须登录后访问系统。
- 不同角色仅能访问授权功能。
- 关键操作应记录日志。
- 涉及设备安全的 Agent 结论必须展示风险提示。

### 10.3 可用性

- 故障上报流程应尽量简洁。
- 运维Agent AI故障上报应避免一次性追问过多问题，额外辅助追问最多 5 轮。
- 诊断结果和维修建议应结构化展示，便于维修人员执行。

### 10.4 兼容性

- Web 端适配主流桌面浏览器。
- Web 端页面应兼顾现场人员和维修人员使用，关键操作页面应保持简洁、表单清晰。
- 导入模板应提供下载示例。

## 十一、效果度量

### 11.1 领先指标

- 故障上报单完整率。
- Agent 诊断结果被设备管理员采纳率。
- 草稿工单确认率。
- 维修建议查看率。
- 知识文档和额定参数配置完整率。

### 11.2 滞后指标

- 平均故障响应时间下降。
- 平均维修时长下降。
- 重复故障排查时间下降。
- 高风险设备故障复发率下降。
- 维修记录知识沉淀数量增长。

## 十二、风险与约束

### 12.1 数据质量风险

人工上报不规范、导入字段不一致、故障码缺失会影响诊断质量。系统需通过必填校验、模板下载、字段校验和 Agent 追问降低风险。

### 12.2 知识库不足风险

早期知识文档和历史案例不足时，专家级维修建议可能覆盖有限。系统需标注依据来源和置信度，并允许人工复核。

### 12.3 Agent 误判风险

Agent 诊断可能存在误判。系统必须保留人工确认机制，Agent 不得直接派发工单。

### 12.4 安全责任风险

新能源装载机涉及高压电、电控、液压、制动等安全风险。系统必须在高风险故障中优先提示停机、安全检查和人工复核。

### 12.5 范围蔓延风险

本阶段仅做故障智能运维，不扩展到车队调度、场站管理、完整备件库存、厂家售后结算和实时车联网。

## 十三、验收标准

### 13.1 设备台账

Given 管理员进入设备台账页面，When 新建设备并填写必填信息，Then 系统应成功保存设备。  
Given 设备编号已存在，When 用户再次使用相同编号创建设备，Then 系统应提示编号重复并禁止保存。  
Given 设备存在未关闭工单，When 用户尝试删除设备，Then 系统应禁止删除并提示原因。

### 13.2 设备知识配置

Given 管理员进入设备知识配置，When 新增 BOM 节点，Then 系统应保存节点并展示树形结构。  
Given 管理员新增额定参数，When 参数编码与同型号已有参数重复，Then 系统应禁止保存。  
Given 管理员在软件系统上传知识文档，When 文档传输到 RAGFlow 并完成解析、切片和索引，Then 软件系统应展示文档状态为已就绪。  
Given RAGFlow 文档解析失败，When Agent 检索知识，Then 该文档不得作为可引用来源。  
Given Agent 生成诊断或维修建议，When 引用 RAGFlow 检索结果，Then 页面应展示来源文档、片段摘要或引用标识。

### 13.3 故障上报与运维Agent

Given 用户使用人工表单上报故障，When 必填字段缺失，Then 系统应禁止提交并提示缺失项。  
Given 用户进入 AI故障上报 Tab，When 用户具备故障上报功能权限，Then Agent 应提示“我可以帮你通过对话生成待提交故障单。请先选择设备。”  
Given 用户进入 AI故障上报 Tab，When 用户无故障上报功能权限，Then Agent 应提示可咨询和整理信息但无法创建 AI待提交 单据。  
Given 用户通过 AI故障上报选择设备，When 打开设备选择器，Then 选择器应展示设备编号、设备名称、所属车间、所属产线且只能选择一台设备。  
Given AI故障上报必填信息已满足，When Agent 准备生成预览，Then 应主动询问是否生成结构化预览并提示非必填缺失项。  
Given Agent 已生成结构化预览，When 用户查看预览，Then 预览应只读，用户只能通过继续对话修改。  
Given 用户确认生成待提交单，When 创建成功，Then 系统应生成正式故障编号并在故障上报列表展示状态 AI待提交。  
Given AI待提交 单据在故障上报页面，When 用户提交，Then 状态应变为待接单且故障编号不变。  
Given 用户使用智能问数，When 用户未说明时间范围，Then 默认按近30天查询并展示统计口径。  
Given 智能问数 API 查询失败，When 存在上一轮成功结果，Then 应保留上一轮结果并提示本次条件未更新。

### 13.4 Agent 权限与运维Agent入口

Given 系统管理员在角色管理中关闭 AI 悬浮框权限，When 对应用户登录，Then 用户不应看到或打开运维Agent入口。  
Given 用户具备 AI 悬浮框权限，When 打开运维Agent，Then 用户可进入 AI故障上报、智能问数、操作指引三个 Tab。  
Given 用户无故障上报功能权限，When 在 AI故障上报中尝试生成 AI待提交 单据，Then Agent 应拒绝创建并用对话说明原因。  
Given 用户使用智能问数，When 查询全局业务数据，Then 系统不按设备负责人或设备范围做数据权限过滤。  
Given 用户在不同页面跳转后再次打开运维Agent，When 未点击清除对话，Then 各 Tab 历史应继续保留。  

### 13.6 Agent 诊断

Given 系统收到完整故障上报单，When Agent 完成分析，Then 应输出故障类型、风险等级、可能原因、置信度和依据来源。  
Given 诊断置信度较低，When 展示诊断结果，Then 系统应标记需人工复核。  
Given 故障涉及高压电池或制动系统，When Agent 输出结果，Then 应包含安全提示和停机建议。

### 13.7 草稿工单

Given Agent 生成维修建议，When 系统生成工单，Then 工单状态应为草稿。  
Given 工单处于草稿状态，When 设备管理员确认并派发，Then 工单状态应变为待接单。  
Given 工单未经过管理员确认，When 系统尝试派发，Then 应禁止派发。

### 13.8 维修执行与知识沉淀

Given 维修人员提交完工，When 实际故障原因或处理方案为空，Then 系统应禁止关闭工单。  
Given 工单关闭，When 系统沉淀维修记录，Then 应生成历史案例或待审核知识条目。

### 13.9 健康评分与驾驶舱

Given 设备存在严重故障码和未关闭工单，When 用户查看设备详情，Then 系统应展示健康分下降和扣分原因。  
Given 管理层进入驾驶舱，When 查看高风险设备 Top 5，Then 系统应展示对应设备及风险原因。  
Given 用户选择时间范围，When 查看故障趋势，Then 系统应按所选范围统计。

### 13.10 用户及权限

Given 账号被停用，When 用户尝试登录，Then 系统应拒绝登录。  
Given 司机/现场人员登录，When 访问用户管理页面，Then 系统应禁止访问。  
Given 系统管理员修改角色权限，When 保存成功，Then 对应用户权限应按新配置生效。
Given 系统管理员或设备管理员在设备台账中选择设备负责人，When 保存成功，Then 对应设备管理员只能查询和上报其负责设备的故障信息。
