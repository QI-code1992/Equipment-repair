# 新能源装载机设备智能运维平台 PRD

- Baseline: Candidate v1.0
- Status: Awaiting Stage 1 user approval
- Date: 2026-07-14
- Source decision records: `workflow/CHANGE_REQUESTS.md`, `workflow/STAGE_APPROVALS.md`

## 1. Product definition

新能源装载机设备智能运维平台面向设备管理、故障处理、维修执行和知识沉淀，提供 Web 端设备台账、故障上报、工单协同、维修记录、统一健康评分、BI 查看和受控智能体能力。软件系统承载业务事实与权限；LangGraph 编排 Agent；RAGFlow 提供知识解析、检索、重排和引用。

## 2. Problem and goals

设备故障信息分散在人工描述、维修记录和知识文档中，处理人员难以及时定位风险、复用经验和追踪闭环。本期目标：

- 建立设备、故障、工单、维修记录和知识文档的闭环。
- 用统一健康分服务提供一致的风险结果和扣分解释。
- 让用户通过人工表单或 Agent 辅助完成故障信息收集。
- 让智能问数只解释后端真实指标，不让模型生成数值。
- 让诊断、维修建议和草稿工单具备依据、置信度和人工确认边界。
- 让菜单/操作权限、设备授予边界和审计日志可追溯。

## 3. Non-goals

- 不建设数据导入菜单、权限、接口或一期开发入口；历史页面只作为 Git 快照追溯。
- 不建设通用数据权限体系，不把设备授予扩展为所有模块的数据过滤。
- 不提供故障单重新打开、指标启停/编辑/删除/版本切换。
- 不纳入无稳定数据源的报警记录、故障码、参数超限、稳定运行逐步恢复等指标。
- 不建设移动端、小程序、车队调度、备件库存和厂商结算。

## 4. Users and roles

| Role | Core need | Key permissions |
|---|---|---|
| 系统管理员 | 管理账号、角色、菜单、配置和全局业务 | 全局菜单/操作管理、审计查看 |
| 设备管理员 | 管理设备、知识、诊断审核和工单派发 | 设备与知识管理、诊断确认、工单派发 |
| 维修工 | 接收并执行维修任务 | 查看授权设备与工单、提交维修记录 |
| 产线作业员 | 快速发现并上报故障 | 查看相关业务、创建人工或 AI 待提交故障 |

设备负责人授予边界仅用于 Agent 的设备查询、故障上报和带入；不构成设备台账、BI 或智能问数的通用数据权限体系。

### P0

- 系统管理、智能配置、菜单/操作权限、审计日志。
- 统一健康分服务和 40 项内置指标只读展示。

### P1

- Windows 演示环境的备份、Tailscale Funnel 临时访问和运维提示。

## 6. Functional requirements

### 6.0 Prototype-aligned page inventory

当前原型基线包含 14 个页面：登录、工作台、驾驶舱 BI、工厂建模、设备台账、新增设备、编辑设备、设备详情、故障上报、Agent 上报、维修记录、维修执行、系统管理、智能配置；全局 Agent 以悬浮抽屉存在。工单没有独立页面，嵌入 BI、故障、维修和设备详情流程。

### FR-001 设备台账

设备编号全局唯一；字段包括名称、型号、类型、厂家、日期、运行小时、状态、负责人和图片。状态为正常、故障、维修中、停用。存在待接单或维修中故障时禁止停用；存在未关闭业务时禁止删除。新增/编辑时可选择设备负责人。

### FR-002 知识配置

支持 BOM、额定参数、知识文档、故障知识、历史案例。文档上传到 RAGFlow 后展示上传、解析、切片、索引和失败状态；未就绪或失败文档不可被 Agent 引用。引用必须包含文档和片段标识。

### FR-003 人工故障上报

故障单字段包括设备、车间/产线带出值、紧急程度、故障现象、发生时间、可能位置、说明和附件。设备与故障现象必填；发生时间不得晚于当前时间；单附件上限 100MB。

### FR-004 AI 故障上报

Agent 通过多轮对话收集一台设备、紧急程度和故障现象，生成只读预览，再生成 AI 待提交单。生成前必须校验故障上报权限；用户只能在故障上报页编辑并正式提交。AI 待提交单提交后进入待接单，故障编号保持不变。

### FR-005 运维 Agent

具备 AI 悬浮框权限的用户可使用三个独立 Tab：AI 故障上报、智能问数、操作指引。关闭弹框不清除历史；清除只影响当前 Tab。无故障上报权限时仍可咨询和整理，但不能生成 AI 待提交单。

### FR-006 智能问数

后端提供 40 项内置指标及允许维度、口径、公式和示例。Agent 只做意图理解、指标匹配、维度校验、追问和结果总结；数值必须来自业务 API。缺少时间范围默认近 30 天；查询失败时保留上一次成功结果并提示未更新。

### FR-007 诊断与维修建议

LangGraph 读取用户、设备、故障和维修上下文，按白名单调用业务 API 和 RAGFlow，输出故障类型、风险、可能原因、置信度、引用依据、排查步骤、维修步骤、安全注意事项、工具/备件和工时/成本。低置信度或高压/制动等风险必须人工复核并提示停机/安全检查。

### FR-008 草稿工单与维修

Agent 只生成草稿工单；设备管理员确认后派发。工单经待接单、维修中、待验收、已完成流转；维修人员必须填写实际原因、处理方案和维修结果后才能关闭。关闭后生成历史案例或待审核知识条目。

### FR-009 健康评分

基础分 100、最低 0。正式上线日所有设备从 100 分建立内部基准，不回算上线前事件。评分周期最近 30 天，历史时间线展示最近 60 天且只记录评分或构成变化。状态扣分、紧急程度风险、逾期风险和重复故障风险独立计算后相加，评分服务异常直接显示计算失败，不使用旧值/0/空值兜底。

等级为：100 正常、80–99 低风险、60–79 中风险、40–59 高风险、0–39 严重风险。工作台、BI、台账、设备详情和智能问数只读取统一服务结果。

### FR-010 系统管理与审计

管理员管理用户、固定角色、菜单和操作权限，记录登录、权限拒绝、设备/知识/工单/维修关键变更。指标口径只读；不得提供指标启停、编辑、删除和版本切换。

### FR-011 工厂建模

管理员维护根节点下的工厂、车间、产线三级组织树，支持搜索、全部展开/折叠、查看详情、新增、编辑、启停和删除。编码全局唯一、同级名称不可重复；停用节点级联停用且不可新增下级；存在下级或历史引用的节点禁止删除。

### FR-012 智能配置中心

管理员在同一配置中心维护 LLM、Embedding、Rerank 模型资源，配置 AI 故障上报、智能问数、操作指引、故障诊断四类 Agent，管理知识库上传/解析/切片/索引/失败重试，查看调用记录与 Token 用量，并只读查看 40 项指标及智能问数查询参数。指标不提供启停、编辑、删除。

## 7. Business rules

- SLA 从故障正式提交时间开始，非常紧急/紧急/一般为 2/4/6 小时。
- 当前紧急程度扣分为非常紧急 -2、紧急 -1、一般 0；处理后立即恢复。
- 未处理逾期风险持续；处理后第 30 个自然日 00:00 恢复。
- 同设备同故障类型滚动 30 天重复风险：重复 1/2/3+ 次扣 3/5/8 分；一般状态不触发。
- 停用设备冻结停用前评分，重新启用后继续计算。
- 评分同一计算时刻合并为一条快照，保存前后值、触发事件、扣分/恢复项、关联故障和计算时间。
- Agent 不得直接写业务事实、修改健康分或绕过人工确认。

## 8. Non-functional requirements

- 安全：权限校验在服务端执行；敏感密钥不进入仓库；保留审计。
- 可解释：诊断和维修建议显示引用、置信度和风险提示。
- 可用：Agent 不可用时人工故障和人工工单流程仍可用。
- 可追溯：每个阶段基线绑定 Git Commit SHA；变更进入统一台账。
- 附件：单文件最大 100MB。
- 演示运维：Windows 环境；每日 00:10 备份，保留 10 天；临时外网访问采用 Tailscale Funnel。

## 9. Product metrics

- 故障上报完成率、AI 待提交转正式提交率。
- 从正式提交到接单、维修完成和关闭的时长。
- 诊断引用覆盖率、低置信度人工复核率。
- 健康分计算成功率、快照可追溯率。
- 智能问数指标匹配成功率和结果 API 错误率。

## 10. Assumptions and open questions

- 首批设备型号、知识文档格式、RAGFlow 部署方式、Embedding/Rerank 模型、LLM 部署方式和 metadata 标准需在 Stage 4 前确认。
- 评分规则已固化，但首批真实设备数据和上线日期需在实施前确认。
- 当前原型是交互证据，不是生产 API 或生产数据实现。
